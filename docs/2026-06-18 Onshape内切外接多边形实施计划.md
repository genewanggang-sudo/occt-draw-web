# Onshape 内切/外接多边形草图工具实施计划

日期：2026-06-18

## 背景

当前草图绘制工具已有 line、rectangle、circle、3 point circle、ellipse、arc、conic 等命令，但还缺少 Onshape 中的 `内切多边形` 和 `外接多边形`。

本计划基于两类输入：

1. Chrome 中接管 Onshape 文档 `f261e49a2decf35fa7ead0d9 / 9d7aaf096835d33267f438a2` 后的实际调试观察。
2. 当前项目代码中的草图命令、DocumentRequest、SketchPrimitiveBuilder、toolbar 和 icon 现状。

## 审查结论

这项功能可以直接实施，但不能按“临时画出闭合折线”的方式实施。专业 CAD 里的正多边形至少要同时满足三层目标：

- 交互层像 Onshape：中心点、参考半径点、边数输入、连续绘制、可取消、可预览。
- 模型层稳定：正式草图仍保存为可参与 profile、选择、删除、undo/redo 的线段拓扑，不把 preview 或参考圆写进正式几何。
- 长期语义可扩展：后续能补等边约束、中心约束、半径/内切圆尺寸、动态输入框和参数编辑，不因为首版实现把数据结构锁死。

因此，本计划不建议只做“默认 6 边 + 两次点击”。那可以作为内部里程碑，但不能作为最终交付标准。可交付的生产级首版应至少支持：

- 内切/外接两种模式。
- 默认边数 `6`，首版不提供输入 UI；`sideCount` 仍必须进入命令状态和 Request 输入，作为后续统一输入规划的预留。
- 创建结果是 n 条真实 sketch edge，能进入现有 profile、选择和编辑链路。
- 几何计算集中在 `@occt-draw/math`，草图写入集中在 `@occt-draw/sketch`/`@occt-draw/cad-model`，editor 只负责交互状态机。

当前项目的其它草图绘制功能暂未提供统一动态输入体验，因此多边形首版也不单独实现边数输入。Onshape 式浮动输入、toolbar 数值输入和键盘输入应后续整体规划；但多边形命令的数据结构和 Request 必须从第一版就携带 `sideCount`，不能把默认 6 边写成不可扩展的常量。

## Onshape 调试观察

在 Onshape 中文界面进入 `Sketch` 后，通过工具搜索 `多边形` 可看到两个草图工具：

- `内切多边形`：说明为“绘制在内切圆上定义的多边形的草图。”
- `外接多边形`：与内切多边形同组显示，图标表现为多边形和参考圆的相对关系不同。

实际交互观察：

- 工具入口位于草图工具栏中的多边形工具组，搜索结果可直接选中。
- 两种工具都使用中心点优先的交互：先点中心，再点半径/参考点。
- 拖动或移动第二点时会显示临时预览，包括多边形、参考圆、中心点、半径方向和动态尺寸输入。
- 默认边数为 `6`。
- 半径点附近会出现长度输入和边数输入；键盘焦点可能落在动态输入上，因此实现时要考虑默认边数、显式输入边数、非法边数处理和回车确认。
- 内切多边形的参考圆穿过多边形顶点，即第二点可理解为外接圆半径点。
- 外接多边形的参考圆与多边形边相切，即第二点可理解为内切圆半径点。

未完全确认但实现前需要复核的细节：

- Onshape 在第二次点击后是否总是要求回车确认，还是只有动态输入被激活时才保留输入状态。
- 边数输入是否支持直接键入后立即确认，例如输入 `5`、`8`、`50`。
- 内切/外接模式在旋转角度上的默认对齐规则是否都以中心到第二点方向作为第一个顶点或第一条边的法线方向。

## 当前项目相关职责

### packages/math

职责：提供 2D/3D 几何基础类型和算法。

当前相关能力：

- `Vec2`、`Circle2`、`Polygon2` 已从 `@occt-draw/math` 导出。
- `Circle2.fromThreePoints(...)` 这类几何构造已放在 math 层。

多边形应新增或扩展的内容：

- 新增规则多边形点列 helper，建议使用纯函数 `createRegularPolygonPoints(...)`，暂不新增可变模型类。
- 输入必须包含 `center`、`referencePoint`、`sideCount`、`mode`。
- `mode = 'inscribed'` 时，`referencePoint` 是顶点所在外接圆上的点。
- `mode = 'circumscribed'` 时，`referencePoint` 是边的内切圆半径方向点，顶点半径需要由 `apothem / cos(pi / n)` 换算。
- 统一校验 `sideCount >= 3`、点有限、半径大于 `MATH_EPSILON`、`cos(pi / n)` 非退化。
- 返回值应是 `GeometryResult<readonly Vec2[]>` 或明确的 `null` 策略，不能抛异常作为常规退化输入处理。

### packages/sketch

职责：维护草图实体、拓扑、显示采样和基础 primitive builder。

当前相关能力：

- `SketchPrimitiveBuilder.addClosedPolyline(points)` 已能创建闭合线环。
- 多边形如果作为若干直线边保存，不需要新增 curve 类型。

多边形应新增或扩展的内容：

- 在 `SketchPrimitiveBuilder` 中新增 `addRegularPolygonByCenterReference(...)`。
- builder 内部调用 math helper 生成点列，再复用 `addClosedPolyline(points)`。
- 不新增专门的 `Polygon2D` curve，不把正多边形保存为单条曲线。
- 保持 change recording 继续走现有 `capture(...)` 和 recorder 机制。
- 后续如果引入约束 solver，应在 builder 层或更高的 sketch edit facade 中追加 equal、coincident、horizontal/vertical、construction circle 等约束记录；不要把约束逻辑塞进 editor command。

### packages/cad-model

职责：把草图修改包装为 Document 级 Request，不让 editor 直接修改 raw Sketch。

当前相关能力：

- `AddClosedLineSegmentsRequest` 已可通过 `target.primitives.addClosedPolyline(...)` 创建闭合线段。
- `AddCircleRequest`、`AddThreePointCircleRequest`、`AddEllipseRequest` 已展示了草图工具到 DocumentRequest 的模式。

多边形应新增或扩展的内容：

- 新增 `AddRegularPolygonRequest`，输入包含 `center`、`referencePoint`、`sideCount`、`mode`。
- Request 内部调用 `SketchPrimitiveBuilder` 的多边形方法，返回 `createdEdgeIds` 和 `payloadId`。
- 不建议让 Request 直接调用 math helper 后复用 `addClosedPolyline`。这样会把草图 primitive 构造策略放进 cad-model，长期会让约束、尺寸和 recorder 逻辑分散。

### packages/editor

职责：命令定义、命令状态机、草图交互、预览 draft、状态更新。

当前相关能力：

- `SketchCircleCommand` 已支持中心点 + 半径点的两点式交互，并支持拖动创建。
- `SketchRectangleCommand` 已支持临时闭合线段 preview。
- `commandTypes.ts`、`commandRegistry.ts`、`editorState.ts` 维护 command id、可用性和 sketch tool state。

多边形应新增或扩展的内容：

- 新增 command id：
    - `sketch-inscribed-polygon`
    - `sketch-circumscribed-polygon`
- 新增 `SketchToolState`：
    - `{ kind: 'inscribed-polygon'; center: Vector2 | null; sideCount: number }`
    - `{ kind: 'circumscribed-polygon'; center: Vector2 | null; sideCount: number }`
- 新增命令类，建议共享内部基类或 helper：
    - `SketchRegularPolygonCommand`
    - 或两个薄命令 `SketchInscribedPolygonCommand`、`SketchCircumscribedPolygonCommand`
- `Application.ts` 中需要注册新命令实例，并扩展 command union 类型。
- 预览 draft 需要显示：
    - 多边形边线。
    - 中心点。
    - 第二参考点。
    - 可选参考圆线段，优先作为临时对象，不写入正式草图。
- `cancel` 行为与 circle 对齐：
    - 已有 center 时，第一次 Esc 清空中心并保留 polygon 工具。
    - 无 center 时，Esc 回到 select。
- 提交后继续留在当前 polygon 工具，并清空 center。
- 键盘输入边数不进入首版；后续方案应尽量复用或抽象出其它命令也能使用的动态输入状态，不要只在 polygon command 内写一次性 DOM。

### packages/ui

职责：通用 UI 组件和 toolbar 图标。

当前相关能力：

- `ToolbarIconId.InscribedPolygon` 和 `ToolbarIconId.CircumscribedPolygon` 已存在。
- `toolbar-icons.svg` 中已有 `cad-toolbar-icon-inscribed-polygon` 和 `cad-toolbar-icon-circumscribed-polygon`。

多边形应新增或扩展的内容：

- 原则上不需要新增图标资源。
- 仅需确认图标在 `SplitIconDropdown` 中渲染正常。

### apps/web

职责：应用壳、workbench UI、命令 toolbar 分组。

当前相关能力：

- `CommandToolbar.tsx` 已按工具组暴露 line、rectangle、circle、arc 等草图命令。

多边形应新增或扩展的内容：

- 在草图绘制工具组中新增 polygon 组或加入现有相关组。
- 推荐新增独立 `多边形` 组，默认入口为 `内切多边形`，下拉包含 `外接多边形`。
- 使用已有 `ToolbarIconId.InscribedPolygon` 和 `ToolbarIconId.CircumscribedPolygon`。
- 首版不提供边数输入 UI；边数输入后续随草图动态输入能力整体规划。

## 长期架构原则

1. 正多边形的数学定义属于 `@occt-draw/math`，不能散落在 editor command 或 cad-model request 中。
2. 正式草图真源应是 points、vertices、line curves、edges；参考圆和半径线是交互 preview 或未来 construction/dimension 语义，不应在首版无约束体系时偷偷写入普通几何。
3. `@occt-draw/sketch` 负责把“规则多边形意图”转换成稳定拓扑，并为未来约束/尺寸接入保留位置。
4. `@occt-draw/cad-model` 只负责编排 DocumentRequest、事务和 payload id，不承载几何公式。
5. `@occt-draw/editor` 只负责状态机、pointer/keyboard 输入、draft preview 和 command result，不直接操作 raw Sketch。
6. `apps/web` 只暴露工具入口和轻量 command option，不应绕过 editor 或 document request。
7. 多边形创建后应自然参与 Profile 识别；Profile 是派生结果，不应由 polygon command 手动维护。
8. 首版不实现约束 solver 时，必须明确“不自动生成等边约束/半径尺寸”；后续补约束时通过 sketch 层扩展，不修改 editor 命令的核心职责。

## 专业 CAD 语义取舍

Onshape 这类 CAD 工具中的多边形不是一条独立“多边形曲线”，而是生成一组草图线段，并通常配合约束、尺寸和动态输入共同维持正多边形意图。本项目当前约束和尺寸体系还未完整，因此应采用分层策略：

- 立即实现：生成真实闭合线段拓扑，保证选择、删除、undo/redo、Profile、后续特征消费链路可用。
- 同步预留：Request 和 command state 保留 `mode`、`sideCount`、`center`、`referencePoint`，首版使用默认 `sideCount = 6`，让后续可以接入统一输入和编辑能力。
- 后续增强：引入 equal length、coincident、中心点、construction circle、radius/apothem dimension、sideCount parameter 或 feature-like sketch metadata。

不建议的做法：

- 只在 editor 中计算 6 个点，然后调用现有闭合线段 Request。
- 把 reference circle 写成普通 circle，导致用户误以为它是正式草图几何。
- 新增 `Polygon2D` curve 并让 profile/选择/渲染都特殊处理，这会偏离草图线段拓扑模型。
- 为 polygon 单独写一个浮动输入 DOM，后续 line、circle、arc 不能复用。

## 几何设计

定义：

- `center`：多边形中心。
- `referencePoint`：第二次点击或拖动位置。
- `sideCount`：边数，默认 `6`，最小 `3`，建议首版最大值限制为 `128`，避免大量边造成交互和 profile 计算压力。
- `mode`：
    - `inscribed`：内切多边形，参考圆为外接圆，顶点在圆上。
    - `circumscribed`：外接多边形，参考圆为内切圆，边与圆相切。

内切多边形点列：

```ts
const radius = distance(center, referencePoint);
const startAngle = atan2(referencePoint.y - center.y, referencePoint.x - center.x);
point[i] = center + radius * [cos(startAngle + i * 2pi / n), sin(startAngle + i * 2pi / n)];
```

外接多边形点列：

```ts
const apothem = distance(center, referencePoint);
const vertexRadius = apothem / cos(pi / n);
const normalAngle = atan2(referencePoint.y - center.y, referencePoint.x - center.x);
const startAngle = normalAngle - pi / n;
point[i] = center + vertexRadius * [cos(startAngle + i * 2pi / n), sin(startAngle + i * 2pi / n)];
```

外接模式的角度选择说明：

- `referencePoint` 表示某条边的中点方向，也就是边的法线方向。
- 用 `normalAngle - pi / n` 作为第一个顶点方向，可让第一条边以 `referencePoint` 方向为切点中心。
- 实现前应用 Onshape 再复核默认旋转方向；如果视觉方向相反，可改为 `normalAngle + pi / n`，但核心半径换算不变。

退化处理：

- `sideCount < 3` 返回 null 或空 result。
- `radius <= MATH_EPSILON` 返回 null。
- 非有限点返回 null。
- 外接模式下 `cos(pi / sideCount)` 过小返回 null，理论上 `sideCount >= 3` 不会接近 0。

## 交互设计

生产级首版应做到：

1. 用户进入 sketch 后选择 `内切多边形` 或 `外接多边形`。
2. 第一次左键点击设置中心点。
3. 移动鼠标时显示多边形预览、中心点和参考点。
4. 首版固定使用默认边数 `6`，不提供边数输入 UI。
5. 第二次左键点击创建闭合线环。
6. 创建后继续停留在当前多边形工具，并继续使用默认 `sideCount = 6`。
7. Esc 规则与 circle 一致。

边数输入分层：

- 必须层：`SketchToolState`、DocumentRequest、math helper 都支持 `sideCount`。
- 首版 UI 层：不提供输入，命令内部使用默认值 `6`。
- 后续统一输入层：整体规划 toolbar/command option、viewport 浮动输入和键盘输入，范围建议 `3..128`。
- Onshape 对齐层：补 viewport 浮动输入，允许在第二点前后键入边数和尺寸。

如果要更接近 Onshape，阶段 2 需要额外设计：

- viewport 浮动输入组件。
- 输入焦点时屏蔽全局快捷键。
- Enter 确认当前多边形。
- Esc 在输入框内先取消输入，再按命令 cancel 规则回退。

连续绘制和状态记忆：

- 切换到内切/外接多边形时，首版统一使用 `sideCount = 6`。
- 创建一个 polygon 后，清空 `center`，保留 `mode`，`sideCount` 仍为默认 `6`。
- 从内切切换到外接时不能共享未完成的 center。
- 退出 sketch 或切换非 polygon 工具时清空未完成输入。

预览对象：

- 多边形边线：使用正式点列生成逻辑，避免 preview 与提交结果不一致。
- 参考圆：只作为 temporary draft，用于表达内切/外接语义，不写入正式 Sketch。
- 中心点和参考点：只作为 temporary draft。
- 半径线：可选 temporary draft，若加入应使用低优先级/辅助色，不参与选择。

目标：确认多边形作为草图线环能进入已有和规划中的 CAD 主链路。

检查项：

- Profile：n 条线段闭合后应被后续 profile solver 识别为一个 loop。

## 交付范围建议

生产级首版必须实现：

- 内切/外接两种命令。
- `sideCount` 数据结构和 Request 输入，首版默认 `6`，不提供 UI 输入。
- 两点式点击和拖动创建。
- preview 和正式闭合线段写入。
- toolbar 暴露。
- undo/redo、删除、选择、Profile 链路验证。

可以暂缓：

- 边数输入 UI，包括 viewport 动态输入、toolbar 数值输入和键盘输入。
- 多边形创建后的约束自动添加。
- 尺寸标注自动生成。
- 与 Onshape 完全一致的输入框焦点和 Enter 行为。

原因：

- 当前项目还没有统一的 viewport 动态输入控件。
- 规则多边形作为闭合线段落地，可以复用 profile、选择、删除、undo/redo 机制。
- `ToolbarIconId` 和 SVG 已具备，UI 成本低。
- 后续 Onshape 式动态输入可以在命令状态已有 `sideCount` 字段的前提下增量实现。

## 不建议直接实施的版本

以下版本不应作为正式实现合入：

- 只在 `SketchInscribedPolygonCommand` 内写死 `sideCount = 6`。
- 正确做法是定义共享默认值，并让 `SketchToolState` 和 `AddRegularPolygonRequest` 仍携带 `sideCount`。
- editor command 自己生成点列并直接复用 `AddClosedLineSegmentsRequest`，没有 math/sketch 层 API。
- 不修改 `CommandAvailabilityContext.activeSketchTool`，导致 workbench 状态无法正确表达 polygon 工具。
- 不注册 `Application.ts` 命令实例，只在 toolbar 暴露按钮。
- 不写退化输入测试，导致 0 半径、2 边形、非有限坐标进入模型。
- 预览点列和提交点列使用两套公式。
