# 产品实施路线与批次门禁

更新日期：2026-07-30

状态：当前唯一有效的实施总纲

## 1. 文档职责

本文件只回答三件事：产品按什么顺序推进、当前应做哪一件事、每个批次怎样安全结束。它不重复描述仓库现状、package 职责或协作细则。

- `README.md` 是当前系统说明和 package 边界的唯一入口；
- `AGENTS.md` 是协作、调研、实现和验收规则的唯一入口；
- 本文件是 `docs/` 下唯一的实施路线图；历史方案只保留在 Git 历史中，不与本文件并列为执行依据；
- Onshape、Autodesk 和其他外部资料，以及每批的调研与验收证据，只放入 Git 忽略的 `tmp/`，并在各目录维护 `INDEX.md`。

## 2. 当前判断

当前工作台已经具备文档、Part Studio、基准面、草图编辑、选择、视图导航和保存/撤销的基础路径。草图模型已经预留 profile 容器和 profile 引用，但尚未生成实际闭合轮廓；编辑器始终将 `hasSketchProfile` 视为 `false`，因此 Extrude 不能进入可执行流程。

与此同时，`c2f47f7` 至 `6adb92a` 的 `@occt-draw/math` 重构已经进入当前代码基线，但尚未完成覆盖全部导出、直接调用方、数值语义和浏览器路径的集成审查。产品能力不能建立在未验收的基础层之上。

因此，接下来的工作只有一个：完成 math 基线集成审查，并冻结一项最小且完整的收口批次。该任务只产出证据和冻结计划，不顺手修改生产代码。审查通过并完成收口后，第一条产品纵向链路才进入“闭合草图轮廓 -> 选择轮廓 -> 可用 Extrude”。

## 3. 有序实施路线

### 阶段 0：math 基线收口

先审查当前已合并 math 改动及其直接 workspace 调用方。若存在违反 owner、根入口、无兼容层或行为保持约束的问题，每次只冻结一项最小收口改动并等待用户审查。阶段完成的标志是：所有确认缺口已逐批关闭，基础 CAD 浏览器路径稳定，且没有遗留双 API、alias、shim、默认服务实例或越界依赖。

### 阶段 1：闭合草图轮廓

在进入实现前，先按固定 Onshape 链接调研闭合轮廓、选择和 Extrude 入口的交互；若跳转到登录页，停止调研并通知用户登录。调研证据写入 `tmp/` 后，冻结 profile 是派生数据还是持久数据的语义、拓扑边界、失效/重建、选择与显示范围。用户可见的完成结果是：普通草图几何形成的有效闭环被稳定识别为可选择的 profile，非闭环和 construction 几何不会误成为 profile，撤销/重做和保存/打开保持一致。本阶段只交付 Profile 的识别、可视化和选择反馈；Extrude 必须保持禁用，直到其命令处理器和特征请求批次完成。

### 阶段 2：从 profile 到特征请求

以已选择 profile 为唯一入口，建立完整的 Extrude 参数、预览、确认与取消链路。此阶段只解决命令状态、文档事务和可持久化的 feature request；不假定几何内核已经具备最终实体生成能力。用户可见的完成结果是：工具可用性、选择、参数面板、预览状态和撤销/重做都与同一 profile 绑定。

### 阶段 3：可执行 Extrude 与实体显示

确认 `occt-draw-core` Wasm 的实际能力和调用契约后，完成 feature request 到内核执行、实体/错误结果、场景投影和持久化恢复的闭环。不能以临时网格、伪实体或跨 package 绕过替代真实特征结果。用户可见的完成结果是：一个有效 profile 能生成、显示、保存、重新打开和撤销/重做真实 Extrude 特征。

### 阶段 4：约束、尺寸与后续特征

在 Extrude 闭环稳定后，再分别推进约束求解、尺寸编辑和后续特征。每项仍以完整工作流为单位冻结，不把架构清理、交互改版和多个产品能力合并为一个批次。

## 4. 每批强制门禁

1. 开始前同步远程并记录当前基线；发现无关本地改动时，先保留并隔离其影响。
2. 涉及产品行为时，先完成必要的 Onshape/Autodesk 调研，资料、截图、脚本、结论和 `INDEX.md` 全部留在 `tmp/`。
3. 冻结一个最小且功能完整的范围：目标、非目标、文件清单、领域 owner、调用方迁移、删除的旧入口和受保护的数据/交互契约必须明确。
4. 先自审冻结计划，检查 package 边界、依赖方向、兼容层、遗漏调用方和范围膨胀；发现问题先修订计划再实施。
5. 不新增或修改测试文件。实现后运行适用的静态检查，并在浏览器完成受影响路径的视觉与交互验收；调研和验收证据写入 `tmp/`。
6. 自审并修复本批全部发现，再报告改动、证据和残余风险。未经用户明确指令，不进入下一批、不提交也不推送。

本次文档整理已获用户明确授权提交；该例外不改变后续产品批次的停点。

## 6. 路线完成标准

- `docs/` 始终只有一份当前有效的实施路线图，且它不与 `README.md` 或 `AGENTS.md` 重复承担同一职责；
- 每个已实施批次都有明确 owner、完整调用方迁移、无兼容层或越界依赖，并保持数据、事务、输入、拾取、GPU/Pass 和可见渲染契约；
- 每个产品阶段以用户可完成的 CAD 工作流验收，而不是以孤立类、占位模型或未验证重构为完成标志；
- 所有外部调研与验收证据可从 `tmp/INDEX.md` 追溯，所有继续实施均经过上一批用户审查。
