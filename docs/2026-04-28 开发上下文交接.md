## 当前状态

当前目标仍是三维云端 CAD 工作台，不是二维出图编辑器。现阶段重点是把 CAD 数据模型、草图内核、编辑事务和视口运行时稳定下来，然后再继续堆草图工具和特征建模。

最近主线已经完成这些收口：

- 删除无实际运行价值的占位包：`shared`、`config`、`cloud-client`、`constraints`、`parametrics`、`protocol`、`wasm-bridge`、`worker-client`、`worker-runtime`。
- 拆出 `@occt-draw/cad-model`，把 CAD 文档、Part Studio、Feature、基准对象、Sketch payload 集成查询从 `core` 中移走。
- `@occt-draw/core` 收缩为通用编辑基础设施：document session、request、transaction、history、edit draft、selection、payload store。
- `apps/web` 已收缩为 React 壳，只依赖 `@occt-draw/editor` 和 `@occt-draw/ui`。
- 视口 canvas、输入事件、ViewCube、渲染图编排和 highlight 编排由 `@occt-draw/editor` 接管。
- 草图目前已有进入草图、选择、直线、矩形、圆、删除、移动点、端点吸附等基础链路。
- 进入草图后的顶部绘制工具栏已按 Onshape 当前草图绘制组收口：`线 / 拐角矩形 / 中心点圆 / 3 点圆弧 / 内切多边形 / 样条`；已实现的直线、拐角矩形、中心点圆接真实命令，其余子项先置灰占位。

## 各包职责

`apps/web`

- React 布局、工具栏、面板容器。
- 不直接创建 canvas。
- 不直接 import `cad-model / sketch / core / math / webgl-engine / cad-canvas / platform`。
- 面板数据通过 editor view model 读取。

`@occt-draw/editor`

- 应用层编辑器。
- 持有命令系统、EditorState、EditorController、ViewportInteractionController。
- 创建并驱动 viewport runtime。
- 把 UI 命令转成 document request。
- 当前命令包括：`select`、`sketch`、`sketch-line`、`sketch-rectangle`、`sketch-circle`。
- 导出草图绘制工具栏配置，未实现的 Onshape 对齐工具只作为 UI 占位，不进入命令系统。

`@occt-draw/cad-model`

- CAD 业务数据模型。
- 包含 `CadDocument`、`PartStudio`、`Feature`、基准对象、默认文档、文档查询。
- 把草图 payload 集成进 Feature History。
- 提供 `AddLineSegmentRequest`、`AddCornerRectangleRequest`、`AddCircleRequest`、`DeleteSketchEntityRequest`、`MoveVertexRequest` 等文档级草图请求。

`@occt-draw/core`

- 通用编辑基础设施。
- 包含 `DocumentSession`、`Request`、`Transaction`、`History`、`EditScope`、`EditDraft`、selection、payload store。
- 不知道 CAD 文档、Feature、Sketch 的业务语义。
- `RequestExecutor` 已删除，request 执行已经折叠进 `DocumentSession`。

`@occt-draw/sketch`

- 草图内核。
- 保存草图平面引用、几何、拓扑、约束占位、尺寸占位、profile 占位、state。
- 草图编辑通过 `SketchEdit -> createSketchEditTransaction(...) -> ModelChangeSet` 形成可回放事务。
- 目前圆是 `Circle2D` 曲线，还没有完整圆选择/约束/profile 求解闭环。

`@occt-draw/math`

- 底层数学和几何。
- 不依赖任何 workspace 包。
- 包含 vector、matrix、plane、curve、polygon、query、approximation。

`@occt-draw/snapping`

- 几何吸附服务。
- 不依赖 sketch/rendering，保持通用。

`@occt-draw/platform`

- 编辑平台层状态和输入辅助。
- 包含选择状态、视图导航状态、屏幕输入到工具链的共享类型。

`@occt-draw/canvas`

- 通用 canvas 渲染运行时。
- 承接 webgl-engine，但不理解 CAD 业务。

`@occt-draw/cad-canvas`

- CAD 数据到 canvas/webgl 渲染图的适配层。
- 负责把 `CadDocument + EditDraft` 投影成可渲染对象。

`@occt-draw/webgl-engine`

- 通用 WebGL2 渲染引擎。
- 只理解 render graph、render object、primitive、pick、highlight、camera 等通用渲染概念。
- 不允许反向知道 CAD、草图、editor。

## 编辑事务链路

当前正式文档编辑走这条链：

```txt
Editor command
-> cad-model Document Request
-> core DocumentSession.execute(...)
-> core Transaction / ModelChangeSet
-> CadDocument
-> cad-canvas projection
-> canvas / webgl-engine render
```

草图编辑不要直接改 `CadDocument`。正确路径是：

```txt
Sketch command
-> AddLineSegmentRequest / AddCircleRequest / ...
-> SketchEdit
-> createSketchEditTransaction(...)
-> mapped Transaction<CadDocument>
-> DocumentSession history
```

`DocumentSession` 是当前 undo/redo、scope、request 执行的中心。后续不要重新引入独立的 `RequestExecutor`。

- 顶点移动。
- 直线端点吸附。
- 草图实体 display model 和基础拾取/高亮链路。

圆命令当前是中心点 + 半径点两步：

```txt
第一次点击：记录圆心
鼠标移动：显示临时圆预览
第二次点击：提交 AddCircleRequest
```

注意：圆目前主要是曲线数据和预览/显示能力，后续还需要补选择语义、约束、尺寸和 profile 识别。

## 当前验证方式

提交前至少跑：

```bash
pnpm -r typecheck
pnpm depcruise
```

大改或推送前优先跑：

```bash
pnpm check
```

浏览器 smoke 优先使用已有 dev server。启动前先检查是否已有前端服务，不要随手开新端口。当前常用地址是：

```txt
http://localhost:5173/
```

浏览器 smoke 最小项：

1. 页面打开后 WebGL2 ready。
2. 默认基准面和 origin 正常显示。
3. 选择基准面，进入草图。
4. 画直线、矩形、圆。
5. 选择草图边/点，inspector 能显示稳定引用。
6. ViewCube、pan、orbit、zoom 不黑屏。

## 下一步建议

优先顺序：

1. 给草图圆补完整显示、拾取和 inspector 信息，确认 circle primitive metadata 稳定。
2. 把 undo/redo 从 `DocumentSession` 接到 editor/UI 快捷键和按钮。
3. 整理命令文案，现在部分新命令仍有临时英文或通用提示。
4. 做 profile 识别基础：封闭线框、圆、矩形都要能形成稳定 profile ref。
5. 再推进约束和尺寸，不要重新创建 `constraints` 占位包；先在 sketch 内核设计清楚约束数据结构。
6. 之后再接特征建模，例如 extrude。

## 明确不要做

- 不要把命令逻辑写回 React 组件。
- 不要让 `apps/web` 直接依赖 CAD 数据模型包。
- 不要让 `webgl-engine` 反向依赖 CAD、草图或 editor。
- 不要恢复已删除的占位包，除非有真实实现和调用路径。
- 不要绕过 `DocumentSession / Request / Transaction` 直接改正式文档。
- 不要把临时预览写入正式文档历史；预览继续走 `EditDraft`。
- 不要引入 Three.js 或 gl-matrix。
- 不要凭记忆匹配 Onshape 交互；关键行为需要实际观察或用户确认。

## 当前协作习惯

- 用户偏好短、直接、基于实际 repo 状态的回答。
- 讨论架构时先给大方向和边界，再讲模块细节。
- 涉及提交时保持提交边界清晰；如果工作区有混合改动，先分组再提交。
- 涉及前端行为时，以浏览器 smoke 和实际交互路径为准。
- 运行 dev server 前先查已有服务，优先复用稳定地址。
