# 草图 Onshape 交互对齐分阶段实施目标

本文用于后续分阶段复制给 Codex 执行。

目标不是新增绘制工具，而是在现有草图能力基础上，把进入草图、退出草图、绘制、预选高亮、选中、确认和取消这些基础交互先对齐 Onshape。行为稳定后，再基于真实差异做架构精细重构。

## 总原则

- 本文阶段只处理现有草图交互体验，不新增 arc、spline、slot、text 等新绘制功能。
- 每个编码阶段开始前，Codex 必须先输出“包职责与改动边界确认”，说明涉及哪些 package/app、改哪些文件或 API、是否改变依赖关系，并等待确认。
- 不新增 workspace package 依赖；如果实现中发现必须新增、删除或改变 package 依赖关系，先暂停说明影响范围和原因。
- 不先做大规模架构重构；优先用当前架构补齐 Onshape 行为，再把暴露出的架构问题整理成后续重构输入。
- 浏览器验收必须覆盖 Onshape 对照和本地实现验证；Onshape 对照使用 `@chrome`，本地实现可使用内置浏览器或 Chrome。
- 不把动态尺寸文本作为本轮必要目标；尺寸文本可以记录为后续阶段。

## 当前包职责与改动边界总览

- `apps/web`：负责草图编辑浮框、确认/取消按钮、显示选项 UI、工具栏显示状态和样式。不承载几何算法。
- `packages/editor`：负责草图编辑 session 状态、命令状态机、选择状态、进入/退出草图行为、草图确认/取消入口。不承载 React UI。
- `packages/core`：仅在确实需要支持编辑 scope 回滚或事务确认/取消语义时修改。不要为了 UI 状态随意改 core。
- `packages/cad-model`：负责文档 request、草图 feature/payload 的创建、删除、编辑请求。不直接处理 DOM 或显示样式。
- `packages/sketch`：负责草图实体模型、几何实体、草图显示模型、曲线采样输出。不处理 React UI。
- `packages/cad-canvas`：负责把 CAD/sketch/draft 转成 canvas scene，保证采样线段的显示和拾取语义能映射回原始 sketch entity。
- `packages/canvas` / `packages/webgl-engine`：仅在现有 highlight/pick 数据结构不能表达“整曲线高亮/选中”时修改；如果需要改 public API，必须先确认。

## 阶段 0：建立 Onshape 行为基准与本地差异表

```txt
目标：用 Onshape 作为草图基础交互规格，记录进入草图、退出草图、绘制、预选高亮、选中、确认、取消的实际行为，并对照当前 occt-draw-web 列出差异。

包职责与边界：
- 只新增或更新 docs 文档。
- 不修改 packages 或 apps 源码。
- 不新增依赖。

执行要求：
1. 使用 @chrome 接管已打开的 Onshape Part Studio 标签。
2. 记录以下行为：
   - 选择基准平面后的左侧树、视口高亮、工具栏状态。
   - 点击 Sketch 进入草图后的顶部工具栏变化。
   - 草图编辑浮框的位置、标题、绿色确认、红色取消、草图平面字段和显示选项。
   - 绘制中心点圆、3 点圆、椭圆时每次点击和 pointer move 后的预览。
   - ESC 对绘制命令和草图编辑 session 的影响。
   - hover 草图曲线时的整曲线高亮颜色和范围。
   - click 草图曲线后的整曲线选中颜色和保持方式。
   - 点击空白区域后的取消选择行为。
   - 绿色确认退出草图后的工具栏、左侧树、视口显示状态。
   - 红色取消退出草图后，新建草图和已有草图的保留/丢弃语义。
3. 使用本地 occt-draw-web 重复相同流程，列出差异表：
   - Onshape 行为。
   - 当前行为。
   - 是否必须对齐。
   - 涉及 package/app。
   - 风险等级。
4. 输出到 docs/草图Onshape交互对齐差异记录.md。
5. 本阶段不运行 pnpm check，除非修改了格式或源码。
```

## 阶段 1：补齐草图编辑浮框 UI

```txt
目标：进入草图后，在视口左上方显示类似 Onshape 的草图编辑浮框，明确表达当前正在编辑哪个草图，并提供确认和取消入口。先完成 UI 框架和状态展示，不实现取消回滚。

包职责与边界：
- apps/web：新增 SketchEditPanel 组件和样式；在 App/WorkbenchLayout 合适位置挂载。
- packages/editor：如现有 workbench view model 信息不足，只补充只读 view model 字段，例如 active sketch 名称、平面名称、当前草图 feature id。
- 不修改 packages/core、packages/cad-model、packages/sketch 的事务或模型。
- 不新增 workspace package 依赖。

实现要求：
1. 只有 editorState.activeSketchSession !== null 时显示草图编辑浮框。
2. 浮框包含：
   - 草图名称，例如 Sketch 1。
   - 绿色确认按钮。
   - 红色取消按钮。
   - 草图平面只读字段，例如 Top plane。
   - 显示约束、显示表达式、显示错误 checkbox 的 UI 占位。
3. checkbox 先只保存 UI 状态或读取默认状态，不要求约束/表达式/错误真实渲染。
4. 绿色确认和红色取消按钮在本阶段可以先接入 no-op 或当前退出行为，但必须在代码注释或 TODO 中明确后续阶段会补完整语义。
5. 样式上浮框不遮挡主工具栏，位置和 Onshape 一致偏左上。
6. 不改变现有绘制命令行为。
7. 使用浏览器验证：
   - 选平面进入草图后浮框出现。
   - 浮框显示当前草图名称和平面。
   - 绘制圆/矩形时浮框仍保留。
   - 退出草图后浮框消失。
8. 运行 pnpm check。
```

## 阶段 2：实现绿色确认退出草图语义

```txt
目标：让草图浮框绿色确认按钮对齐 Onshape：确认当前草图编辑，退出 sketch edit session，恢复普通 Part Studio 工具栏和普通草图显示状态。

包职责与边界：
- apps/web：绿色确认按钮调用 editor 层确认退出草图入口。
- packages/editor：新增或复用确认退出草图的方法，清理 activeSketchSession、draft、绘制命令状态和选择状态。
- packages/cad-canvas：如需要，区分 active sketch 和非 active sketch 的显示风格。
- 不修改 core 事务主链路，除非发现现有 confirmScope 无法表达确认退出。
- 不新增 workspace package 依赖。

实现要求：
1. 点击绿色确认后：
   - activeSketchSession 变为 null。
   - commandSession 回到 select 或普通空闲状态。
   - draft 清空。
   - 草图编辑浮框消失。
   - 顶部工具栏恢复为普通 Part Studio 工具栏。
   - 草图 feature 保留在左侧树。
2. 如果正在绘制命令的中间状态，确认按钮应先取消未完成 draft，再确认退出草图。
3. 不删除已经提交的草图实体。
4. 已提交草图退出后使用普通已确认草图显示风格，不再显示编辑中辅助状态。
5. 如果需要新增 EditorController public 方法，例如 confirmActiveSketchEdit，必须在编码前说明这是 public API 改动并等待确认。
6. 使用浏览器验证：
   - 创建草图 -> 画圆 -> 点击绿色确认。
   - 浮框消失，toolbar 恢复，草图保留。
   - undo/redo 不被异常污染。
7. 运行 pnpm check。
```

## 阶段 3：实现红色取消退出草图语义

```txt
目标：让草图浮框红色取消按钮对齐 Onshape：取消当前草图编辑 session。新建草图未确认时应丢弃本次草图；编辑已有草图时应丢弃本次编辑 session 中的未确认改动。

包职责与边界：
- apps/web：红色取消按钮调用 editor 层取消草图入口。
- packages/editor：负责区分新建草图 session 和编辑已有草图 session，并触发取消流程。
- packages/core：只有在现有 DocumentSession/MutationScope 缺少 cancel/rollback 能力时才修改。
- packages/cad-model：如需要，补充删除草图 feature/payload 或恢复 sketch snapshot 的 request。
- 不新增 workspace package 依赖。

高风险说明：
- 本阶段可能涉及 core 事务/编辑 scope 语义，是高风险阶段。
- 开始编码前必须先确认当前 DocumentSession 是否已有可复用的 scope cancel/rollback 能力。
- 如果需要新增 core public API，必须先输出方案、影响范围和替代方案，等待确认。

实现要求：
1. 新建草图后未确认，点击红色取消：
   - 草图编辑浮框消失。
   - activeSketchSession 清空。
   - 新建草图 feature/payload 从文档中移除，左侧树不再显示该草图。
   - 本次未确认绘制实体全部丢弃。
2. 编辑已有草图时点击红色取消：
   - 恢复进入编辑时的草图状态。
   - 丢弃本次编辑 session 内未确认的新增、删除、移动。
3. 取消不能生成错误的 undo/redo 历史。
4. 已确认过的历史不能被错误清掉。
5. ESC 行为不要直接等同红色取消，除非 Onshape 基准记录证明一致。
6. 使用浏览器验证：
   - 新建草图 -> 画圆 -> 红色取消 -> 草图不保留。
   - 新建草图 -> 画圆 -> 绿色确认 -> 重新编辑 -> 改动 -> 红色取消 -> 已确认草图恢复。
   - undo/redo 状态合理。
7. 运行 pnpm check。
```

## 阶段 4：对齐进入草图与退出草图的整体状态

```txt
目标：让进入草图和退出草图时的全局 UI 状态、选择状态、相机状态、左侧树状态尽量对齐 Onshape。

包职责与边界：
- apps/web：调整 topbar、CommandToolbar、ModelTreePanel、SketchEditPanel 的显示状态。
- packages/editor：调整 EnterSketchCommand、EditorController 状态清理和选择状态。
- packages/cad-canvas：确认 active sketch plane 的显示不干扰草图曲线选择。
- 不新增 workspace package 依赖。

实现要求：
1. 进入草图前：
   - 选择一个基准平面后，左侧树和视口高亮要明确。
   - Sketch 命令只在一个基准平面被选中时可用。
2. 进入草图后：
   - 普通文件按钮和普通 view toolbar 按 Onshape 类似方式隐藏或降级。
   - 草图工具栏显示。
   - 草图编辑浮框显示。
   - 选择状态清理，不把进入前的平面选择继续作为当前草图选择。
   - 相机切到草图平面视角。
3. 退出草图后：
   - 草图工具栏恢复为普通工具栏。
   - 草图编辑浮框消失。
   - draft 和未完成命令状态清空。
   - 已确认草图 feature 在左侧树保留。
4. 左侧树中 active sketch 和普通 sketch 的视觉状态要能区分。
5. 使用浏览器验证：
   - Top/Front/Right 三个平面都能进入草图。
   - 进入后 UI 状态一致。
   - 绿色确认后 UI 恢复一致。
   - 红色取消后 UI 恢复一致。
6. 运行 pnpm check。
```

## 阶段 5：对齐整曲线 hover、预选、选中和取消选择

```txt
目标：草图曲线的 hover、preselect、select 行为对齐 Onshape。圆、3 点圆、椭圆等采样曲线必须按整条 curve 高亮和选中，不能只选中某一段采样线段。

包职责与边界：
- packages/sketch：确认 display model 能把 sampled segments 映射到原始 Curve ref。
- packages/cad-canvas：确保 curve sampled segments 作为同一 curve object 或同一 highlight group 输出。
- packages/editor：确保 selection target 能保留 SketchEntityKind.Curve 语义。
- packages/canvas / packages/webgl-engine：只有现有 highlight/pick 模型无法表达整曲线高亮时才修改。
- 不新增 workspace package 依赖。

实现要求：
1. hover 圆任意位置时，整条圆浅橙色高亮。
2. 点击圆任意位置时，整条圆橙色选中并保持。
3. 鼠标移开后，选中曲线仍保持选中色。
4. 点击空白区域后取消选中，曲线恢复普通颜色。
5. 椭圆和 3 点圆行为同圆一致。
6. 线段、矩形边、顶点的 hover/select 行为不能退化。
7. 曲线采样 segment 只作为渲染细节，不泄漏为业务选择实体。
8. 如果需要修改 RenderHighlightState、SelectionTarget 或 CanvasPickRef public shape，先暂停说明原因和影响范围。
9. 使用浏览器验证：
   - 中心点圆、3 点圆、椭圆均可整曲线 hover 和 select。
   - 点击空白取消选择。
   - Delete/Backspace 删除选中整曲线。
   - undo/redo 删除正常。
10. 运行 pnpm check。
```

## 阶段 6：对齐现有绘制命令的状态机和预览保留

```txt
目标：不新增绘制工具，只把现有 line、rectangle、circle、3 point circle、ellipse 的绘制状态机、预览保持、ESC 行为和 Onshape 对齐到可接受水平。

包职责与边界：
- packages/editor：调整各 Sketch*Command 的状态机、draft 更新、cancel/escape 行为。
- packages/sketch：只在现有采样或 display model 不能支持预览时补充能力。
- packages/cad-canvas：只调整 draft 渲染和点/线/曲线预览表现。
- apps/web：如需要，调整工具栏 active/pressed 状态。
- 不新增 workspace package 依赖。

实现要求：
1. 中心点圆：
   - 第一点后移动鼠标立即有圆预览。
   - 圆心点按 Onshape 风格显示。
   - 第二点提交后命令状态按 Onshape 记录确认。
2. 3 点圆：
   - 第一点后移动已有临时圆预览。
   - 第二点点击后，不需要鼠标移动也应保留可见预览状态。
   - 第三点提交后生成圆。
3. 椭圆：
   - 交互步骤按已确认的 Onshape 对照执行。
   - 第一阶段预览不能显示成普通圆，应保持椭圆语义。
   - 第二阶段预览方向和短轴变化稳定。
4. 线和矩形：
   - 现有行为不能退化。
   - ESC 分阶段取消，最后退出到 select 或保持草图编辑状态，按 Onshape 基准记录处理。
5. 工具栏 active 状态只表示当前 active command，不被“上次选中的工具组主按钮”误导。
6. 使用浏览器验证全部现有草图工具：
   - line
   - midpoint line
   - rectangle
   - center rectangle
   - aligned rectangle
   - center circle
   - 3 point circle
   - ellipse
7. 运行 pnpm check。
```

## 阶段 7：补齐草图显示选项的最小可用语义

```txt
目标：让草图编辑浮框中的显示选项从纯 UI 占位变成可控制显示状态的最小实现，但不实现完整约束求解器和尺寸系统。

包职责与边界：
- apps/web：checkbox 与 editor state 绑定。
- packages/editor：新增草图显示偏好状态，例如 showConstraints、showExpressions、showErrors。
- packages/cad-canvas：根据显示偏好决定是否渲染已有可视辅助对象。
- packages/sketch：只有已有 sketch model 中存在 constraints/dimensions/errors 数据时才接入显示，不新增完整 solver。
- 不新增 workspace package 依赖。

实现要求：
1. 显示约束 checkbox 能控制已有约束图标显示；如果当前没有约束数据，则保持无图标但状态可切换。
2. 显示表达式 checkbox 能控制已有表达式/尺寸文本显示；如果当前没有尺寸文本系统，则只保留状态，不新增尺寸编辑器。
3. 显示错误 checkbox 能控制已有错误标记显示；如果当前没有错误数据，则只保留状态。
4. checkbox 状态在当前草图编辑 session 内保持稳定。
5. 不实现动态尺寸文本输入。
6. 不实现约束求解。
7. 使用浏览器验证：
   - 进入草图后切换 checkbox 不报错。
   - 绘制、选择、确认、取消不受影响。
8. 运行 pnpm check。
```
