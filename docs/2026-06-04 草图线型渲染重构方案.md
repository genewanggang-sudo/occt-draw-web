# 草图线型渲染重构方案

创建日期：2026-06-04

状态：方案文档，未实施。

## 背景

圆心圆弧的 Onshape 预览有两个阶段：

1. 确定圆心后，移动鼠标确定起点/半径时，显示完整的虚线参考圆和实线半径线。
2. 确定起点后，移动鼠标确定终点方向时，完整参考圆消失，只显示最终会生成的实线圆弧。

当前项目已经能表达这两个阶段的语义：`construction` 线型用于参考圆，`solid` 线型用于真实预览线。但是当前渲染实现仍基于原生 WebGL line primitive 加片元丢弃实现虚线，因此只能做到语义一致，不能做到和 Onshape 像素级一致。

后续如果要让草图预览、选中、高亮、隐藏线、中心线等视觉效果都稳定接近成熟 CAD，需要把“线型语义”和“线段渲染管线”分离，并在显示层建立统一的屏幕空间线渲染能力。

## Onshape 参考依据

本地 `docs` 下保存的 Onshape 前端 bundle 中能观察到以下设计点：

- `docs/woolsthorpe.baec8ca135f3f77bba60.js`
    - 存在 `displayProtoArcGraphics`，用于圆心圆弧等草图预览图元。
    - 预览参考圆和参考线通过 construction 语义传入显示实体。
    - 存在 `CONSTRUCTION_LINE_STIPPLE`、`DEFAULT_LINE_STIPPLE`、`SKETCH_PREVIEW_COLOR` 等显示常量。
    - shader 相关片段使用 `edgeLength`、`lineStipple`、`isGap`、`uLineFilterWidth` 控制线型间隔和抗锯齿过滤。

- `docs/webgl.cb17e4d077a949b1db67.js`
    - 存在 construction line stipple 与 default line stipple。
    - WebGL 层持有 line stipple、filter width 等渲染参数。

这里不复制 Onshape 代码，只把可验证的架构结论作为参考：Onshape 不是简单设置 SVG/CSS 虚线，而是在显示数据和 WebGL shader 层传递线型参数，并用屏幕空间长度、stipple 和 filter width 控制最终视觉。

## 当前实现现状

当前本项目已经新增了线型语义链路：

```txt
packages/core
  DraftLineStyle = "solid" | "construction"

packages/canvas
  CanvasLineStyle = "solid" | "construction"

packages/cad-canvas
  DraftRenderAdapter 按 lineStyle 和 color 分组输出 CanvasEdgeObject

packages/webgl-engine
  EdgeStyle.lineStyle
  RenderMaterial.lineStipple
  shader 根据 line distance 和 stipple 丢弃 gap fragment

packages/editor
  SketchCenterPointArcCommand 在圆心圆弧第一阶段标记 construction 参考圆
```

这条链路的价值是：业务命令只表达“这条线是参考线”，渲染细节由显示层决定。

当前限制也很明确：

- 原生 WebGL line 的线宽、端点、连接、抗锯齿能力受浏览器和显卡限制。
- 当前虚线依赖采样线段的累计距离，能表达 dash/gap，但不能稳定控制端帽、连接处、边缘软化。
- 当前 line distance scale 是基于相机视野估算的屏幕比例，不是完整的屏幕空间线网格。
- 当前选中、高亮、普通边、预览边没有完全使用同一套线渲染模型。

因此，当前方案是短期可用实现，不是最终显示架构。

## 重构目标

目标不是单独修圆心圆弧，而是建立一套 CAD 草图线型显示架构：

```txt
语义层
  solid / construction / hidden / center / hover / selected

显示对象层
  CanvasEdgeObject 携带 lineRole / lineStyle / color / width intent

渲染样式层
  EdgeStyle 解析为 color / widthPx / stipple / aaWidth / depth policy

WebGL 渲染层
  屏幕空间线网格
  shader 控制宽度、dash、gap、cap、join、抗锯齿
```

最终效果：

- construction 参考圆在不同缩放级别下 dash 长度稳定。
- 线宽、端帽、dash 边缘和抗锯齿由 shader 统一控制。
- 草图预览、已生成几何、选中、高亮、隐藏线使用同一类线渲染能力。
- editor 命令不包含任何 WebGL 细节。

## 包职责与改动边界确认

### packages/core

职责：只表达草图 draft 的业务语义。

保留或扩展：

- `DraftLineStyle`
- `DraftLineSegmentObject.lineStyle`

禁止放入：

- dash 数组
- WebGL uniform 名称
- 像素线宽
- shader 相关常量

依赖变化：不改变。

### packages/canvas

职责：承接从 CAD 业务显示对象到渲染图对象的公共 DTO。

后续扩展：

- `CanvasLineStyle`
- 可增加 `CanvasLineRole`，例如 `preview`、`model`、`selection`、`highlight`。
- 可增加 `widthIntent` 或 `displayPriority`，用于表达显示意图，不直接表达 shader 细节。

依赖变化：不改变。

### packages/cad-canvas

职责：把 draft、sketch display、selection display 转成 canvas render graph。

后续调整：

- 继续按 style/color/role 分组，减少 draw call 和材质切换。
- 不在这里写 stipple 数组。
- 不在这里做屏幕空间几何展开。

依赖变化：不改变。

### packages/webgl-engine

职责：实现所有线渲染细节。

后续新增：

- `LineStyleToken` 或 `LineRenderStyle`
- `StyledLineRenderer`
- `ScreenSpaceLineGeometryBuilder`
- line shader 中统一处理 width、stipple、cap、join、AA。

这是重构的核心包。

依赖变化：不改变。

### packages/editor

职责：只根据交互阶段标记线的语义。

保留：

- 圆心圆弧第一阶段的参考圆使用 `lineStyle: "construction"`。
- 圆心圆弧第二阶段的真实弧预览使用默认 `solid`。

禁止放入：

- dash pattern
- WebGL 常量
- 线宽像素值

依赖变化：不改变。

## 分阶段实施计划

### 阶段 1：稳定当前线型语义链路

目标：确认当前 `DraftLineStyle -> CanvasLineStyle -> EdgeStyle -> RenderMaterial` 链路没有职责越界。

实施内容：

- 保留 `solid` 和 `construction` 两种语义。
- 检查所有调用点，确保只有需要参考线的 draft segment 设置 `construction`。
- 圆心圆弧第一阶段：参考圆为 construction，半径线为 solid。
- 圆心圆弧第二阶段：圆弧预览为 solid，不显示完整参考圆。

验收：

- `pnpm check` 通过。
- 浏览器截图覆盖圆心圆弧两个阶段。

### 阶段 2：抽出 webgl-engine 线型 token

目标：把线型常量集中到 webgl-engine，避免散落在材质、shader、renderer 中。

新增或调整：

```ts
export type EdgeLineStyle = 'solid' | 'construction';

export interface LineRenderStyle {
    readonly widthPx: number;
    readonly stipple: readonly [number, number, number, number];
    readonly antialiasWidthPx: number;
}

export function resolveLineRenderStyle(style: EdgeLineStyle): LineRenderStyle;
```

规则：

- `solid` 使用连续线。
- `construction` 使用 Onshape 语义一致的 dash/gap pattern。
- 所有 pattern 单位按屏幕像素理解。

验收：

- 业务包不 import 这些 token。
- 当前视觉不回退。

### 阶段 3：实现屏幕空间线段几何

目标：停止依赖原生 WebGL line 宽度，改为用 triangle mesh 渲染线。

核心思路：

```txt
输入线段：
  start, end, cumulativeDistance, style

展开为屏幕空间 quad：
  start-left
  start-right
  end-left
  end-right

shader：
  根据屏幕空间到线中心距离计算 alpha
  根据 cumulativeDistance 和 stipple 判断 dash/gap
```

需要支持：

- 固定屏幕像素线宽。
- 固定屏幕像素 dash/gap。
- 端点 cap。
- 断开的 segment 不共享 dash 相位。
- 连续采样曲线可以共享 dash 相位。

验收：

- construction 圆的虚线在缩放时长度稳定。
- 半径线和圆弧线仍保持 solid。

### 阶段 4：替换 styled edge 渲染路径

目标：让普通 edge、draft edge、preview edge 走统一屏幕空间线渲染。

实施内容：

- `CanvasEdgeObject` 中的线段不再直接进入原生 line buffer。
- `webgl-engine` 根据 `EdgeStyle` 选择 screen-space line material。
- 原生 `LINES` 只保留为临时兼容路径，最终移除。

验收：

- 线、矩形、圆、三点圆、椭圆、三点圆弧、圆心圆弧都正常显示。
- 删除、undo、redo 不受影响。

### 阶段 5：统一选中、高亮和隐藏线

目标：selection/highlight 不再拥有独立且不一致的线条视觉逻辑。

实施内容：

- 选中线条使用相同 screen-space line renderer。
- hover/selected 只是不同 `LineRenderStyle`。
- hidden/center/construction 作为后续可扩展 line style。

验收：

- 曲线仍按整段业务曲线选中，不暴露采样 segment。
- hover 和 selected 的线宽、颜色、抗锯齿稳定。

### 阶段 6：对齐 Onshape 圆心圆弧预览

目标：以 Onshape 圆心圆弧两个阶段作为视觉基准。

验收场景：

- 第一阶段：完整 construction 参考圆，dash 分布稳定；半径线为 solid。
- 第二阶段：完整参考圆消失，仅显示 solid 圆弧；显示圆心、起点、终点点标记。
- 不做动态尺寸文本。
- 浏览器截图与 Onshape 截图并排确认。

## 风险点

- 深度排序：草图线、模型边、preview、selection 的绘制顺序必须稳定。
- picking：显示线宽变粗后，拾取语义仍应基于业务曲线或已有 picking 规则，不能变成采样 segment。
- 性能：曲线采样后展开为 quad 会增加顶点数，需要批处理和材质分组。
- DPI：`devicePixelRatio`、浏览器缩放、相机投影会影响屏幕像素换算，必须统一入口。
- join/cap：圆、圆弧、折线、矩形需要不同连接处理，不能只做单段 quad。

## 当前结论

当前实现适合作为第一阶段：它已经把草图线型语义从 editor 传到了 webgl-engine，能让圆心圆弧预览行为和 Onshape 保持一致。

如果目标是像素级接近 Onshape，下一步必须重构 webgl-engine 的线渲染管线，核心不是再调 dash 数组，而是把原生 line 渲染替换为屏幕空间线网格和统一 shader。
