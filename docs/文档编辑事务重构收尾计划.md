# 文档编辑事务重构收尾计划

## 文档目的

本文只描述本轮文档编辑事务重构的收尾工作。

本轮目标不是继续扩展长期架构，而是把当前已经落地的 `DocumentEditor / DocumentRequest / MutationScope / preview` 主链路收干净，确保后续草图功能开发可以基于稳定入口继续推进。

长期方向继续参考：

- [文档编辑事务架构重构方案](./文档编辑事务架构重构方案.md)

## 本轮完成目标

业务层应该只看到：

```txt
Command
  -> DocumentRequest
  -> DocumentEditor.execute(request)
  -> DocumentEditor.preview(request)
```

业务层不应该再看到：

```txt
begin / finish
RequestExecution
transaction.apply
手动创建 Transaction
手动写入 History
raw mutable Sketch
raw mutable Store
```

完成后，新增一个草图功能时，理想只需要改：

```txt
1. 新增或修改 DocumentRequest
2. 新增或修改 SketchPrimitiveBuilder / 模型方法
3. 必要的显示或采样适配
```

不应该修改：

```txt
DocumentEditor
MutationScope
Transaction
History
ChangeSet
Request 执行流程
```

## 当前已完成的主线

当前代码已经具备：

```txt
DocumentEditor
DocumentRequest
DocumentWriteContext
MutationScope
DocumentEditor.execute(...)
DocumentEditor.preview(...)
legacy Request 兼容
```

草图相关请求已经迁移到 `DocumentRequest` 风格，editor 预览也已经开始走 `DocumentEditor.preview(...)`。

本轮剩余工作主要是收紧边界和清理残留，不再做大范围架构发散。

## 剩余任务

### 1. 收紧 SketchWriteTarget

当前风险：`SketchWriteTarget` 仍可能暴露 raw model，例如：

```txt
sketch
partStudio
feature
planeObject
```

这会导致业务代码绕过 `target.primitives` 直接修改 raw `Sketch`，从而破坏受控写入口和 change recording。

目标结构：

```ts
export interface SketchWriteTarget {
    readonly partStudioId: PartStudioId;
    readonly sketchFeatureId: FeatureId;
    readonly payloadId: FeaturePayloadId;
    readonly plane: Plane3;
    readonly primitives: SketchPrimitiveBuilder;
}
```

要求：

- `SketchWriteTarget` 不暴露 raw `Sketch`。
- `SketchWriteTarget` 不暴露 raw `PartStudio`。
- `SketchWriteTarget` 不暴露 raw `Feature`。
- 正式修改只能通过 `target.primitives` 或受控 write facade。
- 如确实需要查询能力，单独提供 read target 或只读查询方法，不与 write target 混用。

完成标准：

```txt
DocumentRequest 不能直接拿到 raw mutable Sketch。
DocumentRequest 修改 Sketch 只能走 primitives / write facade。
```

### 2. 统一 preview 入口

当前目标：所有预览型 working document 都必须通过：

```ts
DocumentEditor.preview(request).workingDocument
```

需要清理的旧写法：

```ts
request.execute(...).transaction.apply(...)
```

要求：

- editor 层不再散落手动 `request.execute + transaction.apply`。
- `EditDraft.workingDocument` 统一由 `DocumentEditor.preview(...)` 生成。
- legacy preview 如仍存在，必须封装在 `DocumentEditor.previewLegacy(...)` 或等价内部兼容层中。

完成标准：

```txt
全局没有 editor command 直接手写 request.execute(...).transaction.apply(...)
```

### 3. 降低 TrackedSketchPrimitiveBuilder 漏记录风险

当前风险：tracking 依赖子类 override：

```ts
class TrackedSketchPrimitiveBuilder extends SketchPrimitiveBuilder
```

如果未来 `SketchPrimitiveBuilder` 新增：

```txt
addArc
addSpline
addConstraint
```

但忘记在 tracked 子类中 override，就可能漏掉 change recording。

推荐改法：

```ts
new SketchPrimitiveBuilder(sketch, { recorder })
```

让 `SketchPrimitiveBuilder` 自身接收 recorder 或 change hook，在内部统一 capture mutation。

如果本轮不做该改法，至少要：

- 在 `TrackedSketchPrimitiveBuilder` 附近写清楚约束。
- 新增 primitive mutation 方法时必须同步接入 recorder。

完成标准：

```txt
新增 SketchPrimitiveBuilder mutation 方法时，不容易漏掉 change recorder。
```

### 4. 保留 legacy 兼容，不急着删除

当前阶段不要急于删除：

```txt
legacy Request
DocumentSession
RequestExecution
```

这些仍可作为过渡层存在。

要求：

- 新草图功能优先走 `DocumentRequest`。
- legacy 只作为兼容层。
- 不在新业务中继续扩散 legacy request 写法。

完成标准：

```txt
旧功能不坏。
新功能不新增 legacy Request 写法。
```

## 界面验收路径

本轮不强制以单测作为唯一标准，但必须通过以下界面 smoke：

```txt
1. 打开页面，默认文档正常显示。
2. 选择基准面，进入草图。
3. 画直线。
4. 画矩形。
5. 画圆。
6. 选择草图点，拖动顶点，预览正常。
7. 松开后正式提交，图形更新。
8. 删除草图边或点。
9. undo / redo 正常。
10. ViewCube / orbit / pan / zoom 不受影响。
```

## 本轮非目标

本轮不做：

```txt
ModelChangeSet 完全纯数据化
ModelChangeApplierRegistry 全面替换 runtime target
BaseModelElement tracked property 全面重构
ModelElementStore tracked store 全面重构
DocumentSession 完全删除
MutationScope 完全内部化
约束求解器
Profile 识别
特征重算
```

这些属于下一轮底层深化或后续 CAD 功能阶段。

## 本轮完成判断

满足以下条件即可认为本轮重构完成：

```txt
1. Command 只创建 DocumentRequest。
2. 正式提交走 DocumentEditor.execute(request)。
3. 预览走 DocumentEditor.preview(request)。
4. editor 不手写 request.execute(...).transaction.apply(...)。
5. DocumentRequest 不接触 begin / finish / RequestExecution。
6. DocumentRequest 不直接拿 raw mutable Sketch。
7. 新增草图功能不需要修改 DocumentEditor / MutationScope / Transaction / History。
8. 界面 smoke 通过。
```

达到以上标准后，可以继续推进草图功能开发。后续 core 深化应另起阶段，不再混入本轮收尾。
