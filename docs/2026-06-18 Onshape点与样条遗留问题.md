# Onshape 点与样条遗留问题

日期：2026-06-18

## 目的

记录 Point / Spline 这一轮实现后，仍未完全对齐 Onshape、暂不在本轮继续修复的问题，供后续单独收敛。

## 已完成但不再作为遗留问题的内容

- Point 与 Spline 已能在草图中绘制。
- Point 与 Spline 已拆成两个独立工具入口，不再共用一个下拉主按钮。
- Point 工具图标已按 Onshape 风格改为蓝色圆点/白色内芯语义，不再使用早期外圈方案。
- Point / Spline 工具顺序已从“最前面”后移，不再阻塞当前实施。

以上内容后续如果要继续微调，只属于视觉微调，不再算“功能未落地”。

## 仍未修复的问题

### 1. 草图 Point 渲染仍未与 Onshape 完全一致

现状：

- 当前本地 free point 已改成蓝色空心圆风格。
- 但和 Onshape 实测截图相比，仍存在“外径、描边粗细、蓝色亮度/饱和度”偏差。
- 目前效果比最初的白点或实心点明显更接近，但还没有达到“一模一样”。

已确认的偏差方向：

- 本地点环整体仍偏细。
- 同等截图倍率下，本地点环视觉占比仍略小。
- ring 的蓝色与 Onshape 的标准草图蓝并未完全重合。

影响包：

- `packages/cad-canvas`
- `packages/canvas`
- `packages/webgl-engine`

建议修复方式：

- 不要继续凭肉眼微调单个 magic number。
- 需要固定一套 Onshape 对照样本：
    - 同一缩放倍率
    - 同一 DPR
    - 同一背景色
    - 同一截图裁剪方式
- 然后按像素级对照修正：
    - `sizePixels`
    - outer ring threshold
    - inner hole threshold
    - stroke soft edge
    - point color token

完成标准：

- 同一组测试点在并排截图中，视觉外径和环厚基本重合。
- 缩放后仍保持稳定，不出现某个倍率接近、另一个倍率明显跑偏。

### 2. Point 渲染实现还缺少稳定的视觉基准

现状：

- 当前 ring point 已有基础测试，但主要验证“能渲染出 ring”，不是“与 Onshape 等效”。
- 如果后续有人改 shader 或 point style，现有测试不足以防止视觉回退。

问题本质：

- 现在缺的是“项目自己的基准”，不是缺一个更复杂的 helper。
- 没有基准图和量化阈值，后续每次改 point 都会重新陷入主观争论。

影响包：

- `packages/webgl-engine`
- `packages/cad-canvas`
- `docs`

建议修复方式：

- 新增一份固定的点渲染验收基准文档或测试说明。
- 明确记录：
    - 参考 Onshape 截图来源
    - 浏览器缩放
    - 设备像素比
    - 本地测试页面
    - 允许偏差
- 如条件允许，再补一个基于截图或 raster 结果的回归测试。

完成标准：

- 后续改 point 渲染时，不需要重新靠人工回忆 Onshape 效果判断对错。

### 3. Fit Spline 与 Onshape 的数学一致性尚未完成最终锁定

现状：

- 当前已落地 `FitSpline2` 和草图 spline 绘制链路。
- 但“同一组 fit points 是否与 Onshape 生成完全相同曲线”这一点，还没有形成最终可复用的对照结论。
- 如果后续继续推进样条编辑、约束、插点、切线控制，这个问题会变成更大的维护风险。

风险：

- 如果 `FitSpline2` 的参数化、端点处理、退化策略与 Onshape 不一致，后面功能越多，返工成本越高。
- 一旦 sketch snapshot、编辑命令、选择语义都围绕当前实现扩展，再改底层曲线行为会影响更大。

影响包：

- `packages/math`
- `packages/sketch`
- `packages/editor`
- `docs`

建议修复方式：

- 用固定的 Onshape 测试文档做几组典型样本：
    - 3 点
    - 4 点
    - 多点且转折明显
    - 点间距不均匀
- 对比内容不能只看“像不像”，要至少覆盖：
    - 端点位置
    - 中段弯曲趋势
    - 局部最大偏移
    - 采样点误差
- 如果发现不一致，再决定是：
    - 调整 `FitSpline2` 参数化
    - 调整插值边界条件
    - 还是保留现实现状但在文档中明确与 Onshape 的差异

完成标准：

- 至少有一套固定样本能说明：当前 `FitSpline2` 是否已和 Onshape 对齐。
- 后续继续做 spline 编辑时，不再需要先回头质疑 math 基线。

## 当前不建议重复排查的事项

以下内容本轮已调整过，不建议再作为“未修复问题”重复投入：

- Point / Spline 工具是否拆开：已拆开。
- Point / Spline 是否还放在最前面：已后移。
- Point 图标是否还是旧的外圈样式：已改。

如果后续要继续动这些内容，应该作为“微调”，不是“补漏”。

## 建议后续处理顺序

1. 先锁定 Point 的像素级视觉基准，因为这是当前最明确、最直接可验收的问题。
2. 再锁定 `FitSpline2` 与 Onshape 的数学一致性，因为这是后续样条长期迭代的基础。
3. 最后再补 point/spline 的更细视觉 polish，避免在底层基线未稳定前反复返工。
