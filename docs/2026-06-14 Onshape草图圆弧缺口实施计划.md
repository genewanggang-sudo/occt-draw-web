# Onshape 草图圆弧缺口实施计划

日期：2026-06-14

## 背景

当前项目已经实现并挂载到草图工具栏的圆弧工具：

- `3 点圆弧`：`sketch-3-point-arc`，对应 `SketchThreePointArcCommand`。
- `圆心圆弧`：`sketch-center-arc`，对应 `SketchCenterPointArcCommand`。

对照 Onshape 圆弧下拉菜单，还缺：

- `相切圆弧`
- `椭圆弧`
- `圆锥`

本计划只整理实施边界和步骤，不开始编码。

## Chrome 观察记录

观察环境：用户已打开并登录的 Onshape 文档标签页 `codex调试用1 | Part Studio 1`。

### 圆弧菜单

Onshape 草图编辑状态下，圆弧工具组下拉菜单顺序为：

1. `3 点圆弧`
2. `相切圆弧`
3. `圆心圆弧`
4. `椭圆弧`
5. `圆锥`

### 相切圆弧

操作过程：

1. 先绘制一条普通线段作为相切参考。
2. 从圆弧菜单选择 `相切圆弧`。
3. 点击已有线段的端点作为起点。
4. 移动鼠标时，Onshape 显示从该端点延续出来的圆弧预览，并保持与上一条线段相切。
5. 预览阶段显示半径标注，例如 `R101.499`。
6. 点击终点后生成实体蓝色圆弧，并保持相切圆弧工具激活。

实现含义：

- 起点不应只是任意点，优先要求选择已有边的端点。
- 需要从共享端点关联的已有曲线求切向方向。
- 生成结果仍然是普通圆弧拓扑边，只是构造方式不同。
- 起点应复用已有 vertex，终点创建新 vertex。

### 椭圆弧

操作过程：

1. 从圆弧菜单选择 `椭圆弧`。
2. 点击中心点。
3. 移动并点击主轴端点；预览显示完整虚线椭圆和中心到主轴点的参考线。
4. 移动并点击次轴点；预览继续显示完整虚线椭圆，并显示主/次轴尺寸。
5. 在完整椭圆上选择弧起点。
6. 移动鼠标时，完整椭圆仍以虚线作为参考，只突出显示当前椭圆弧段。
7. 点击弧终点后，只生成选定的椭圆弧段。

实现含义：

- 几何输入可沿用现有完整椭圆的 `centerPoint`、`primaryAxisPoint`、`secondaryPoint`。
- 还需要在椭圆参数域中记录 `startAngleRadians` 和 `endAngleRadians`。
- 实体结果应是开放曲线边，具有 start/end vertex。
- 预览需要区分 construction 风格的完整椭圆参考线和实体弧段。

### 圆锥

操作过程：

1. 从圆弧菜单选择 `圆锥`。
2. 点击第一个端点。
3. 移动到第二个端点时，Onshape 预览一条从第一点到当前点的圆锥曲线。
4. 点击第二个端点后，移动鼠标选择控制点/肩点。
5. 预览阶段显示 `0.5` 数值框，表示圆锥曲线的 rho/权重参数。
6. 点击第三个控制点后生成蓝色圆锥曲线段。

实现含义：

- 最小交互输入是 `startPoint`、`endPoint`、`shoulderPoint`。
- 初版可以固定 rho 为 `0.5`，与 Onshape 默认预览一致；后续再支持可编辑 rho。
- 数学表示建议使用二次有理 Bezier / conic segment，而不是把圆锥近似成普通圆弧。
- 实体结果应是开放曲线边，具有 start/end vertex。

## 当前代码现状

### `packages/math`

已有：

- `Arc2`
- `Ellipse2`
- `EllipticalArc2`
- `sampleCurveSegments2`

缺口：

- 缺少从椭圆点反求参数角的 helper。
- 缺少通过“相切方向 + 起点 + 终点”构造圆弧的 helper。
- 缺少圆锥曲线段模型，例如 `Conic2` 或 `RationalQuadraticBezier2`。

### `packages/sketch`

已有：

- `Curve2DSnapshot` 支持 `line`、`circle`、`ellipse`、`arc`。
- `Curve2D` 子类支持 `Line2D`、`Circle2D`、`Ellipse2D`、`Arc2D`。
- `SketchPrimitiveBuilder` 支持 line、circle、3 point circle、arc、ellipse。
- display 层通过 `sampleSketchCurveSegments` 采样曲线。

缺口：

- `Curve2DSnapshot` 没有 `elliptical-arc` 和 `conic`。
- 没有 `EllipticalArc2D`、`Conic2D` 模型。
- 没有 add elliptical arc / add conic / add tangent arc primitive。
- 当前完整椭圆通常作为 curve 存在，椭圆弧和圆锥需要作为 edge-backed open curve。

### `packages/cad-model`

已有：

- `AddThreePointArcRequest`
- `AddCenterPointArcRequest`
- `AddEllipseRequest`

缺口：

- 缺少 `AddTangentArcRequest`。
- 缺少 `AddEllipticalArcRequest`。
- 缺少 `AddConicRequest`。

### `packages/editor`

已有：

- 命令注册、可用性判断、command reducer message。
- `SketchThreePointArcCommand`
- `SketchCenterPointArcCommand`
- `SketchEllipseCommand`
- 草图工具状态 `three-point-arc`、`center-arc`、`ellipse`。

缺口：

- 缺少 command id、工具状态、命令类和交互流程：
    - `sketch-tangent-arc`
    - `sketch-elliptical-arc`
    - `sketch-conic`
- 相切圆弧需要读取已有草图端点/边关系以求切向方向。
- 椭圆弧需要五阶段状态机。
- 圆锥需要三阶段状态机。

### `packages/ui`

已有：

- `ToolbarIconId.TangentArc`
- `ToolbarIconId.EllipseArc`
- `ToolbarIconId.CircleConic`
- 对应 SVG symbol 已存在。

缺口：

- 无需新增图标。

### `apps/web`

已有：

- `CommandToolbar.tsx` 中圆弧工具组只挂载 `3 点圆弧` 和 `圆心圆弧`。

缺口：

- 需要把 `相切圆弧`、`椭圆弧`、`圆锥` 加入同一个圆弧下拉组。

## 前置问题

正式编码前建议先确认以下边界：

1. `conic` 的数学模型名称：建议使用 `Conic2`，内部按二次有理 Bezier 表示，字段为 `startPoint`、`endPoint`、`shoulderPoint`、`rho`。
2. `conic` 初版是否固定 `rho = 0.5`：建议固定，以匹配观察到的 Onshape 默认流程；后续再做尺寸/参数编辑。
3. 相切圆弧的起点约束：建议初版要求起点必须命中已有 edge 的 endpoint；不支持从孤立点启动。
4. 椭圆弧方向：建议按 Onshape 鼠标选择顺序保留有向 sweep，不强制最短弧；如果用户需要始终最短弧，需要单独确认。

这些前置点如果不确认，容易导致公共快照格式和交互语义返工。

## 分阶段实施

### 阶段 1：几何基础

目标：

- 补齐 `math` 可表达和采样三类曲线。

工作：

- `Arc2` 增加相切构造 helper。
- `Ellipse2` / `EllipticalArc2` 增加点到角度、由中心轴点与起止点构造椭圆弧 helper。
- 新增 `Conic2`，支持：
    - `pointAt(t)`
    - `tangentAt(t)`
    - `bounds()`
    - `isValid()`
    - 默认 `rho = 0.5`
- 为新增几何添加 focused tests。

验收：

- 退化输入返回 null/empty。
- 采样点有限且可渲染。
- bounds 覆盖采样点。

### 阶段 2：草图模型和持久化

目标：

- 新曲线能进入 sketch snapshot、undo/redo、display sampling。

工作：

- 扩展 `Curve2DSnapshot`。
- 新增 `EllipticalArc2D`、`Conic2D`。
- 扩展 `curveFromSnapshot`。
- 扩展 `sampleSketchCurveSegments`。
- `SketchPrimitiveBuilder` 新增三个 primitive 方法。

验收：

- 新曲线可创建、snapshot、fromSnapshot。
- open curve 均创建 edge 和 start/end vertex。
- 删除 edge 时能删除对应 curve 和孤立 vertex。

### 阶段 3：文档请求

目标：

- 新实体创建走统一 document request。

工作：

- 新增三个 request。
- 保持 transaction id 与现有命名一致。

验收：

- request 执行后 payload revision 增加。
- 返回 createdCurveId / createdEdgeId。

### 阶段 4：editor 交互命令

目标：

- 对齐 Onshape 的预览和点击流程。

工作：

- `SketchTangentArcCommand`
    - 进入后等待已有端点。
    - 从端点关联 edge 求 tangent。
    - 移动时显示圆弧预览和定义点。
    - 点击终点提交 request。
- `SketchEllipticalArcCommand`
    - 阶段：center -> primary axis -> secondary axis -> start angle -> end angle。
    - 前三阶段显示完整虚线椭圆参考。
    - 后两阶段显示完整虚线椭圆和实体椭圆弧段预览。
- `SketchConicCommand`
    - 阶段：start -> end -> shoulder。
    - 第二阶段显示 start 到当前点的临时 conic。
    - 第三阶段显示 conic 预览，rho 初版为 `0.5`。

验收：

- ESC 行为与现有工具一致：
    - 有部分输入时清空当前工具输入，仍留在工具中。
    - 无部分输入时退回 select。
- 左键拖动/点击行为不破坏已有 line、arc 工具。

### 阶段 5：工具栏挂载

目标：

- Onshape 圆弧下拉菜单补齐三项。

工作：

- `CommandToolbar.tsx` 圆弧组顺序调整为：
    1. `3 点圆弧`
    2. `相切圆弧`
    3. `圆心圆弧`
    4. `椭圆弧`
    5. `圆锥`
- 使用已有图标：
    - `ToolbarIconId.TangentArc`
    - `ToolbarIconId.EllipseArc`
    - `ToolbarIconId.CircleConic`

验收：

- 菜单显示顺序与 Onshape 一致。
- 选中后主按钮图标跟随上一次选择。

### 阶段 6：浏览器验收

目标：

- 在本地 web app 中做实际交互冒烟。

工作：

- 进入草图。
- 相切圆弧：先画线，再从端点创建相切圆弧。
- 椭圆弧：完整走五阶段。
- 圆锥：完整走三阶段。
- 验证预览、落点、ESC、重复绘制。

验收：

- 三类工具都能生成可见曲线。
- 曲线可被现有选择/高亮逻辑命中。
- 无控制台错误。

## 建议实施顺序

1. 先做 `math` 和 `sketch`，因为这是数据模型和持久化基础。
2. 再做 `cad-model` request，保持 editor 不直接写 model。
3. 再做三个 editor command。
4. 最后挂 toolbar 和浏览器验收。

1. 同意按上述包职责与改动边界实施。
2. 同意不新增或改变 package 依赖关系。
3. 同意 `conic` 初版采用 `rho = 0.5` 固定值。
4. 同意相切圆弧初版只支持从已有 edge endpoint 启动。
5. 同意椭圆弧按用户点击顺序保留有向 sweep。
