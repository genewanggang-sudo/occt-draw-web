# 待优化问题记录

## 待优化问题

1. 刷新页面时，中间画布会闪一下，且整块呈蓝色。
2. 刷新页面 -> 移动或旋转一下 -> 点击基准面 -> 点击进入 Sketch 后，基准面和新增草图面的渲染存在问题，需要确认。
3. 绘制 3 点圆弧时，预览状态和确定后的颜色一样；Onshape 使用两种不同颜色。当前实现中，预览时线较粗、点较大，确认后点变小、线变细，与 Onshape 效果不一致，需要调试 Onshape 确认实现后再考虑当前实现如何修改。
4. 完成草图后，草图面显示消失没有问题，但草图中绘制的线颜色没有变化；需要查看 Onshape 中完成草图后的显示方式，并作为一个需要修改的点。
5. 绘制中点线时，预览和确认后的效果与 Onshape 不一致；当前可能是数据层和渲染层都未完善，需要思考如何完善该功能。

## Onshape 观察结论

1. 活动草图面：大尺寸淡蓝透明面，蓝色边框，显示草图名。
2. 完成草图后：活动草图面消失，草图线显示为灰色；默认基准面仍按其自身可见性显示。
3. 编辑草图中：欠约束草图线主要显示为蓝色；选中/高亮时可显示橙色；顶点为蓝色点。
4. 3 点圆弧：流程为起点、终点、半径点；预览不是当前项目这种亮蓝大点效果，确认后进入普通草图实体显示。
5. 中点线：流程为先放中点，再放端点；预览显示整条对称延伸的浅蓝线、中点标记和动态长度标注；确认后保留中点语义表现。

## 问题与方案

### 1. 刷新时画布蓝色闪一下

原因：

- `createDefaultEditorState()` 初始 viewport size 是 `1x1`。
- `EditorViewport` 构造后立即 `sync()`，先按错误尺寸/相机渲染一帧，再由 `ResizeObserver` 更新真实尺寸后重渲染。

方案：

- 首次渲染前从 host/canvas 读取真实尺寸初始化 navigation。
- 或让 `EditorViewport` 等首个 `ResizeObserver` 尺寸回调后再执行首次 render。
- 保持首帧背景色与 WebGL 清屏色一致，避免初始化空档出现异常色块。

影响包：

- `packages/editor`
- 可能涉及 `apps/web` 初始化传参，不改变依赖关系。

### 2. 点击 Sketch 后草图面和绘制结果不可见

原因：

- 已按路径复现：刷新 -> 触发一次相机导航 -> 选择 `Front plane` -> 点击 Sketch 后，状态为 `命令：Sketch`，显示对象为 `13 个`，`SketchEditPanel` 正常显示，但画布首帧只有两条蓝色十字线，active sketch plane 的淡蓝面/边框不可见。
- 在该状态下点击 Line 并绘制，状态会变为 `命令：Line`，显示对象增加，属性面板元素数量也增加，但线段首帧仍不可见。
- 只要再滚轮缩放一次，不改变 Sketch 状态，草图面和已绘制线段会立刻出现；canvas CSS 尺寸和 WebGL buffer 尺寸前后不变，排除布局尺寸滞后。
- 根因集中在 `EnterSketchCommand.createSketchPlaneCamera()`：进入 Sketch 时它直接复用进入前相机的 `near/far`，但同时把 `position/target/up/orthographicHeight` 切到基准面正视图。
- `near/far` 是依赖当前相机方向、位置和当前 display bounds 的裁剪范围，不能跨视角复用；刷新后先平移/缩放会让旧视角的 clipping 被重算，进入 Sketch 后裁剪范围与新草图相机不匹配，导致草图面和草图线首帧被裁剪或没有完整进入可见绘制结果。
- 后续滚轮能恢复，是因为 `ViewNavigationController.zoom()` 会通过 `withFramedCamera()` 调用 `frameCameraClippingToBounds()`，重新按当前草图相机和当前 display bounds 计算 clipping。

方案：

- 进入 Sketch 生成草图相机后，必须立刻按即将显示的 bounds 重新计算 `near/far`，不能复用旧相机的 clipping。
- 优先把进入 Sketch 的相机切换收敛到 `ViewNavigationController.setCamera()` 或同等的 `frameCameraClippingToBounds()` 路径，保证和滚轮/旋转/适配视图的 clipping 逻辑一致。
- 如果 `EnterSketchCommand` 当前拿不到进入 Sketch 后的完整 display bounds，需要在 editor 层新增一个明确的“应用命令结果后重算相机裁剪范围”的步骤，而不是在 render 层靠下一次导航补救。
- 回归用例：刷新 -> 平移/缩放或旋转 -> 选基准面 -> Sketch 后，不移动视图也必须立即显示 active sketch plane；随后点击 Line 绘制，预览和确认结果也必须立即可见。
- 该问题不应通过调高 active sketch plane 透明度、调整颜色或强制二次 render 掩盖；核心修复是进入 Sketch 后相机 clipping 与当前 display bounds 对齐。

影响包：

- `packages/editor`
- 可能涉及 `packages/canvas` 的相机 framing helper 复用；不改变依赖关系。

### 3. 3 点圆弧预览与确认后颜色/点大小不一致

原因：

- 预览走 `DraftRenderAdapter`，确认后走 `SketchRenderAdapter`。
- 两套路径分别硬编码颜色和点大小，没有统一的 sketch visual token。
- 当前预览点更大、颜色更亮，确认后点变小、颜色仍偏蓝，和 Onshape 的预览/实体状态不一致。

方案：

- 抽出统一草图视觉样式：`previewGeometry`、`activeUnderconstrained`、`selectedSketchEntity`、`inactiveSketch`。
- Draft 和 committed sketch 使用同一套状态化样式，不再各自硬编码。
- 3 点圆弧预览应使用浅蓝/青色预览线，确认后按普通活动草图实体显示。
- 点大小需要按 Onshape 调整：预览不应比确认后显著粗大。

影响包：

- `packages/cad-canvas`
- `packages/editor`
- 不改变依赖关系。

### 4. 完成草图后线颜色没有变化

原因：

- `confirmActiveSketchEdit()` 只清空 `activeSketchSession`。
- `SketchRenderAdapter` 不知道当前 sketch 是 active 还是 inactive，所有草图线都使用同一蓝色。

方案：

- `PartStudioRenderAdapter` 将 `activeSketchFeatureId` 传给 `SketchRenderAdapter`。
- `SketchRenderAdapter` 按 active/inactive sketch 选择样式。
- inactive/完成草图线改为灰色；active/editing 草图线按约束状态显示蓝/黑/红，并支持选中高亮橙色。

影响包：

- `packages/cad-canvas`
- `packages/editor`
- 不改变依赖关系。

### 5. 中点线数据层和渲染层不完善

原因：

- 当前 `SketchMidpointLineCommand` 确认后只提交 `AddLineSegmentRequest`。
- 数据层没有记录“中点线”或 midpoint constraint。
- 预览只画普通线段，没有中点标记、对称关系和动态长度标注。

方案：

- 数据层新增中点线语义，优先方案是新增 midpoint constraint，而不是把中点线做成特殊线类型。
- 新增或扩展请求，例如 `AddMidpointLineRequest`，创建线段时同时创建中点约束/中点参考点。
- 预览层显示完整对称线段、中点标记、动态长度标注。
- 确认后渲染层能根据约束/点语义显示中点点位，并按普通草图实体样式显示线段。

影响包：

- `packages/sketch`
- `packages/cad-model`
- `packages/editor`
- `packages/cad-canvas`
- 会新增或修改跨包 Request/API 和 sketch 数据模型，实施前必须单独确认。
