## 当前结论

当前草图基础交互已经达到“可以停止继续堆功能，转入架构整理”的状态：

- 进入草图、退出草图、确认、取消主路径稳定。
- 绘制工具主路径稳定，包括线、矩形、圆、3 点圆和椭圆。
- 曲线选择已经以原始 curve 为业务选择实体，不再把采样 segment 泄漏给用户选择语义。
- 显示选项已经从纯 UI 状态提升为 editor session 状态。

当前不建议马上新增更多草图工具。更合理的下一步是处理下面这些已经暴露出来的结构性问题。

## 后续重构输入

### math 曲线契约和 tolerance 策略

当前圆、3 点圆、椭圆已经能完成基础绘制，但后续要支撑约束、尺寸、捕捉、投影和稳定编辑，`math` 需要更明确的曲线契约。

建议后续整理：

- 统一 2D 曲线接口：点求值、切线、法线、参数域、包围盒、最近点、采样。
- 区分“几何曲线”和“显示采样线段”，避免业务层依赖采样结果。
- 明确 tolerance 的单位和缩放策略，例如模型空间距离、屏幕空间拾取半径、归一化参数误差不能混用。
- 为退化几何定义统一失败语义，例如三点共线圆、零半径圆、零轴长椭圆、近似重合点。
- 给 circle / ellipse / line 的构造 helper 增加一致的 `Result` 或显式空值策略，减少 command 层重复判断。

### core edit scope / transaction / rollback 契约

红色取消语义已经可用，但当前 command、document request、scope、history 之间仍然需要更清楚的契约，避免后续新增复杂编辑器时继续堆条件判断。

建议后续整理：

- 明确 edit scope 的生命周期：begin、confirm、cancel、undo、redo 各自对 document 和 history 的影响。
- 明确“新建后未确认”和“编辑已有对象后取消”的通用 rollback 规则。
- 把 scope 内 request 的历史标签和最终 confirm/cancel 历史标签策略固定下来。
- 增加针对 sketch edit scope 的回归测试：新建取消、确认后再编辑取消、删除后取消、移动后取消、undo/redo 穿越 scope。
- 避免 UI command 直接理解过多 transaction 细节，controller 应该提供更稳定的编辑边界 API。

### cad-canvas / canvas / webgl-engine 的 pick 与 highlight 语义

整曲线选择现在可用，但当前实现仍然依赖 cad-canvas 把曲线采样 segment 分组输出，并通过 highlight 层做特殊处理。后续如果加入约束、尺寸、profile、更多曲线类型，需要把 pick/highlight 语义系统化。

建议后续整理：

- 明确 `CanvasObject.id`、`interactionId`、`primitiveMetadata`、`pickGranularity` 的职责边界。
- 把“显示对象”和“业务选择实体”的映射关系文档化，尤其是 sampled curve、topology edge、vertex、dimension、constraint。
- 统一 hover、preselect、select 三种 highlight 的输入模型，减少 editor 对特定 sketch entity kind 的特殊判断。
- 明确整曲线高亮是 display group 语义，不应由 webgl-engine 理解 CAD/sketch 业务类型。
- 为 curve group pick 增加小型渲染适配测试，保证后续新增 spline/arc 不破坏整曲线选择。

### editor command state machine 复用点

阶段 6 暴露出多个 `Sketch*Command` 存在相似状态机：进入工具、第一点、预览、提交、部分取消、回到 select。当前每个命令独立实现，短期可控，但继续新增工具会快速复制复杂度。

建议后续整理：

- 抽出草图绘制命令的共同生命周期：enter、pointer down/up/move、preview draft、commit、partial cancel、exit to select。
- 保留各工具自己的几何构造逻辑，不把所有命令塞进一个巨型 command。
- 统一 command message、draft 清理、active sketch tool 切换和 ESC 行为。
- 为“一次点击提交”和“多步点击提交”的命令定义清楚的状态转移表。
- 把 toolbar active 状态只绑定 `activeCommandId` 的规则固化，避免 split button 选择记忆再次污染真实命令状态。

## 建议下一步

阶段 8 之后，不建议直接进入更多草图工具开发。建议先开一个架构重构阶段，优先级如下：

1. `editor` command state machine 复用点梳理。
2. `core` edit scope / rollback 回归测试补齐。
3. `math` 曲线契约和 tolerance 策略整理。
4. `cad-canvas` / `canvas` / `webgl-engine` pick 与 highlight 语义收敛。

这些工作应分别做包职责与改动边界确认，避免把编辑器状态、数学几何、渲染拾取和 UI 行为再次混在同一轮里。
