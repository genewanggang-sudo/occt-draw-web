## 当前产品方向

项目目标是三维云端 CAD 工作台，不再做二维出图编辑器。

已确认方向：

- 页面：React
- 构建：Vite
- 包管理：pnpm workspace
- Node/npm/pnpm 管理：Volta，仅对当前项目生效
- 渲染：原生 WebGL，不引入 Three.js

- 文档、产品文案和工程文档：中文

## 最近架构收口

最近完成的 WebGL 引擎重构：

- `webgl-engine` 的公开入口已收口：推荐使用 `RenderEngine / RenderGraph / RenderLayer / RenderableObject / RenderObjectBuilder / FaceSet / EdgeSet / PointSet / MarkerSet / TextLabelSet` 等类；`GeometryBuffer / GeometryBufferBuilder / RenderMaterialResolver / RenderMaterial / RenderState` 不再从主包入口导出，保持为内部实现。
- `RenderableObject<TGeometry, TStyle>` 已作为可扩展渲染对象基类落地，使用方通过继承对象类并重写 `build(builder)` 和 `computeBounds()` 扩展图元。
- `RenderObjectBuilder` 已收口为公开 type-only 扩展契约，只暴露 `faces / edges / points / lines / markers / labels`，不暴露构造函数、内部 context、queue、buffer 或 material resolver。
- `FaceSet / EdgeSet / PointSet / MarkerSet / TextLabelSet` 都已经走 `RenderableObject` 协议；`RenderQueueBuilder` 不再通过 `instanceof FaceSet / EdgeSet / PointSet / MarkerSet / TextLabelSet` 中心化识别内置图元。
- `TextLabelSet` 虽然已走统一对象协议，但 label 顶点仍保留 atlas / camera / viewport 相关的专用生成路径，不伪装成普通 `GeometryBuffer`。
- 文档中已补完整 `CurveSet extends RenderableObject` 示例，说明外部扩展方只依赖主包导出的 `RenderableObject / RenderObjectBuilder / RenderObjectOptions / GeometryBounds` 等公开类型，不需要 deep import 内部模块。
- `RenderQueue / DrawCommand` 已作为内部队列落地，`ColorPass` 消费 queue，不直接理解 CAD 业务对象。
- `RenderBackend / WebGLRenderer` 已作为内部后端边界落地，`RenderEngine` 继续作为公开调度入口。
- `RenderMaterial / RenderState` 已作为内部 style-to-backend 语义落地，公开 API 仍保留 `FaceStyle / EdgeStyle / PointStyle / MarkerStyle / TextStyle`。
- `WebGLResourceRegistry` 已集中管理 WebGL program、buffer、VAO、label atlas、buffer cache 和 navigation depth 资源生命周期。
- `HighlightPass / OverlayPass / ViewCube` 已通过 backend immediate draw 绘制，不再直接依赖 pass context 中的 raw WebGL resource。
- `RenderPassContext` 已不再暴露 `WebGL2RenderingContext`，pass 只表达“画什么”，backend 负责“怎么画”。
- `packages/editor` 已落地，避免命令逻辑散落在 React 组件中。
- `cad-rendering` 作为业务渲染层，主入口已切到 `CadDocument + EditDraft -> RenderGraph`。
- `apps/web` 主链路通过 `RenderEngine.setGraph(graph) / setHighlight(highlight) / render(camera)` 驱动视口。
- 独立 `renderer` 包已删除；原相机、包围盒、拾取、渲染输入协议已下沉到 `webgl-engine`。
- `webgl-engine` 是可复用 WebGL2 渲染引擎包，只依赖 `math / shared`。
- `webgl-engine` 主模型是 `RenderGraph / RenderLayer / RenderObject`，不依赖 `cad-rendering / core / sketch / editor / apps-web`。
- 主渲染已经 graph-native，不再每帧把 `RenderGraph` 转回旧 `RenderScene`。
- 渲染管线已 pass 化，顺序为 `ColorPass -> HighlightPass -> OverlayPass`。
- `HighlightPass` 直接消费真实 `RenderHighlightState`，负责 hover / preselect / select 高亮。
- `RenderObjectPicker` 和 `NavigationDepthSampler` 已直接遍历 `RenderGraph`。

- `RenderObject` 支持 `interactionId` 和 `pickGranularity`，用于把多个渲染对象收敛为同一个交互对象。
- 默认场景已移除调试立方体、坐标轴、地面网格，只保留基准面和原点。

## 草图架构设计最新上下文（2026-05-07）

当前开始从 WebGL 收口转向草图系统大重构。用户明确要求不要继续在半迁移草图模型上小修小补，而是先把草图架构设计想清楚，再作为后续草图功能开发基础。

最新草图设计方向：

- `Sketch` 是核心领域对象，不再使用 `PlanarSketch` 命名；平面属性由 `SketchPlane` 表达。
- 草图是 `Feature History` 中 `SketchFeature` 的 payload，不应该长期放在 `EditorState.sketchesById` 这种临时编辑器状态里。
- 草图核心包含：`SketchPlane / SketchEntities / SketchConstraints / SketchDimensions / SketchProfiles / SketchState`。
- `SketchEntities` 内部分为 `GeometrySet` 和 `TopologySet`：
    - `GeometrySet` 保存 `Point2D[] / Curve2D[]`。
    - `TopologySet` 保存 `Vertex[] / Edge[]`。
- 图中只画包含关系；引用关系、派生关系、数据流关系不混在一张图里，避免交叉线和抽象混乱。
- 命令流程统一为：`SketchCommand -> SketchRequest -> SketchTransaction -> Sketch -> cad-rendering`。
- `SketchRequest` 表达一次业务编辑请求，可以直接操作 `Sketch` 及内部模型数据。
- `SketchTransaction` 代表一次可记录提交，并持有本次提交生成的 `SketchChangeSet`。
- `SketchChangeSet` 是一次提交的增删改记录集合，不是散落的 type union；后续应抽象为类。
- `HistoryManager` 管理 `SketchTransaction`，框架层统一处理 undo / redo。
- undo / redo 的目标模型：增删改记录必须能精确表达：
    - 增：新增了哪个对象及完整快照。
    - 删：删除了哪个对象及删除前快照。
    - 改：修改了哪个对象、哪个属性路径、旧值、新值。
    - 框架按规则统一反转：增->删，删->增，改->旧值/新值切换。

最新文档状态：

- `docs/草图架构设计.md` 已被清空后重写为新的架构图底稿。
- 当前只保留少量核心图：设计依据、草图模块总架构、草图内核对象关系、命令到渲染数据流、草图变更记录与撤销重做。
- 这份文档还不是完整实施方案，后续需要继续补：核心类定义、目录结构、请求/事务/变更类体系、文档持久化方案、迁移步骤和验收标准。

## 工作平面当前状态

`math.Plane` 当前是类实例，不再只是一个无限数学平面的最小表达。

当前属性：

- `origin: Point3`
- `normal: Vec3`
- `xAxis: Vec3`
- `yAxis: Vec3`

构造入口：

- `new Plane(origin, normal, xAxis?)`
- `createPlane(origin, normal, xAxis?)`

构造时会做统一正交化：

- `normal` 归一化。
- `xAxis` 投影到平面内再归一化。
- `yAxis = normal.cross(xAxis)`。
- 非法 normal、零向量、平行 xAxis 会回退到稳定默认轴。

当前方法：

- `signedDistanceToPoint`
- `projectPoint`
- `intersectRay`
- `localToWorld`
- `worldToLocal`
- `projectPointToLocal`

兼容函数仍保留：

- `signedDistanceToPlane`
- `projectPointToPlane`
- `intersectRayWithPlane`

CAD 对象层：

- `ReferencePlaneObject` 仍然是文档对象，包含 `origin / normal / xAxis / size / planeKind`。
- `size` 只表达显示面片尺寸，不进入 `math.Plane`。
- `core.referencePlaneToPlane(object)` 负责把 `ReferencePlaneObject` 转成标准 `Plane`。

## 默认基准面当前状态

当前默认基准面仍是 `ReferencePlaneObject`，不是直接把 `Plane` 存进文档。

语义约定：

- Top：XY / XOY 平面。
- Front：ZX / XOZ 平面。
- Right：YZ / YOZ 平面。

`planeKind` 暂时保留，用于名称、默认文案和兼容；新的坐标转换应优先使用 `Plane.localToWorld / worldToLocal`，不要继续按 `planeKind` 到处硬编码坐标映射。

## Text Label 当前状态

基准面文字当前目标是接近 Onshape 的效果：

- 使用 WebGL 贴图文字，不使用 DOM overlay。
- 文字跟随基准面旋转。
- 文字参与 depth test，可被前方几何遮挡。
- 文字屏幕大小基本固定，不随模型缩放变大变小。
- 文案保持英文：`Top / Front / Right`。

当前实现链路：

```txt
reference-plane
  -> cad-rendering 映射为 TextLabelSet
  -> RenderGraph label/helper layer
  -> LabelAtlasManager.ensureForGraph(...) 生成 Canvas2D 文字贴图
  -> labelGeometry 生成 3D textured quad
  -> ColorPass label shader 绘制贴图文字
```

当前 label 模型：

```txt
frame + insert + justify + heightPixels + paddingPixels + fontWeight
```

语义：

- `frame`：文字所在局部坐标系，包含 `origin / xAxis / yAxis`，都是世界坐标语义。
- `insert`：文字在 frame 内的插入点，单位是局部世界单位，不是像素。
- `justify`：文字如何挂到插入点上，包含水平、垂直和 baseline 语义。
- `heightPixels`：文字屏幕高度，用于保持视觉字号稳定。
- `paddingPixels`：文字盒子沿 frame 轴向的屏幕像素内边距，会在渲染时转成世界单位。
- `fontWeight`：字体粗细，当前支持 `100..900` 的数值字重；切换字重会按需重建 atlas，不预生成所有字重。

当前默认基准面 label：

- `fontWeight: 400`
- `heightPixels: 15`
- `paddingPixels: { x: 6, y: 6 }`
- label frame 放在基准面左上角，`yAxis` 为反向，使 `vertical: 'top'` 更符合贴角阅读语义。

当前已经处理过的点：

- 不再使用无语义的 `anchor + offsetPixels` 模型。
- 已支持文字 padding。
- 已支持传入 fontWeight。
- 文字字号已调小，字重已调细。
- atlas 不预生成所有字重，当前按显示模型中出现的字重按需重建。

## 相机导航当前状态

默认相机和标准视图已切到 Z-up，鼠标导航已完成一次收口。

当前代码状态：

- rotate / pan begin 时解析一次操作中心，拖动过程中固定使用该中心。
- rotate 会让 `position` 和 `target` 一起绕操作中心旋转，避免第一帧把视图中心拉回模型中心。

- clipping / fit 使用 `RenderGraph.navigationBounds`，不依赖旧 `RenderScene`。
- navigation depth 已 graph-native，overlay layer、label 和 `navigationRole === 'excluded'` 的对象不参与采样。
- navigation depth 和 ViewCube overlay 已接入 `webglStateGuard`，避免 WebGL 全局状态泄漏导致后续主渲染黑屏。

## 关键架构理解

### EditDraft

`EditDraft` 是命令执行过程中的临时编辑层。

它不是 UI，也不是 renderer。它用于承载：

- 鼠标移动过程中的临时线段
- 拖动过程中的临时位置
- 可取消的草图预览
- 后续约束求解过程中的临时 working document

标准规则：

- `pointerDown` 创建或初始化 `EditDraft`
- `pointerMove` 更新 `EditDraft`
- `pointerUp` 生成正式 `DocumentOperation`
- `Esc` 丢弃 `EditDraft`

### Operation

`DocumentOperation` 不是 Request。

```txt
Request/Input：用户刚刚做了什么输入
Command：当前命令如何解释输入
EditDraft：命令过程中的临时数据
Operation：最终写入 CAD 文档的正式业务动作
Transaction：一次原子提交
TransactionGroup：一个用户动作包含多次提交
```

拖动 300 次不应该产生 300 条历史。拖动过程更新 `EditDraft`，确认后只提交一次 `Operation` 或 `TransactionGroup`。

### CAD Rendering

`cad-rendering` 的职责只有一个：理解 CAD 业务对象，并把正式文档和临时编辑层转换为引擎可消费的通用渲染数据。

```txt
CadDocument + EditDraft -> cad-rendering -> RenderGraph -> webgl-engine
```

`cad-rendering` 不知道 React、不直接操作 WebGL、不知道 CommandManager，也不修改 `CadDocument`。

`cad-rendering` 可以理解 CAD 业务语义，例如 reference plane、origin marker、sketch line。它负责映射为业务无关的 `RenderGraph / RenderObject`：

```txt
reference plane -> FaceSet / EdgeSet, depthRole = secondary
origin marker / sketch line / draft line -> MarkerSet / EdgeSet / PointSet, depthRole = primary
label / annotation -> TextLabelSet, depthRole = excluded, pickable = false
```

`webgl-engine` 不允许反向依赖 `cad-rendering`，也不允许接收 `CadObject / Sketch / Feature` 等 CAD 业务实例。

### Editor

`editor` 是编辑器运行时包。

它不负责 UI，也不是 CAD 文档模型。它承接 UI 之外的编辑器交互能力：

- 当前命令和命令生命周期
- 鼠标、键盘、视图输入解释
- 选择状态和命令状态流转
- `EditDraft` 创建、更新和取消
- `DocumentOperation / DocumentTransaction` 提交入口

目标是让 `apps/web` 只负责产品装配、界面展示和事件转发。

### 已确认的相机导航设计

- 普通 rotate 不使用固定世界 Z 轴；水平旋转绕当前 `camera.up`，垂直旋转绕当前 `camera.right`。
- `pointerDown` 时解析一次 `rotateOrPanCenter`，drag 过程中固定使用该中心。
- 不使用长期累积的旧 `orbitPivot` 作为 rotate begin 的默认来源。
- `camera.target` 表示当前视图中心语义；`orbitPivot` 表示当前 rotate/pan 操作中心；`sceneCenter/sceneRadius` 用于 fit、clipping 和 fallback。
- rotate 时 `position` 和 `target` 一起围绕 `orbitPivot` 旋转，避免第一帧把视图中心强行拉回 pivot。
- pan 使用 rotate/pan center 所在的 view-normal plane，保持 pan 和 rotate 中心语义一致。
- wheel zoom 使用本次鼠标位置解析出的 `zoomAnchor` 保持鼠标下内容稳定，但不写回长期 `orbitPivot`。
- pan / rotate / zoom / fit / standard view 后都会重新按当前 camera forward 和 navigation bounds 刷新 `near/far`。

### 当前 orbit center 解析顺序

当前实现接近 Onshape 的普通 free orbit 结构：

1. 鼠标附近矩形先做 `primary` depth sampling，命中则取离鼠标最近的 `worldPoint`。
2. 鼠标附近没有 primary 样本时，再允许 `secondary`，取离鼠标最近的 `worldPoint`。
3. 鼠标附近仍无样本时，对整个 viewport 做稀疏 depth sampling，先 `includeSecondary=false`。
4. primary 窗口样本不足时，再 `includeSecondary=true`。
5. 窗口样本足够时，对 `worldPoint` 求平均作为中心。
6. 仍失败时使用 navigation bounds center。
7. bounds 不适合时，用鼠标射线按 bounds center 深度计算 fallback 点。
8. 最后兜底 `camera.target`。

当前阈值：

- 鼠标附近采样半径：`12px`
- 窗口旋转中心采样：`viewport-grid`
- 窗口目标样本数：`2000`
- 窗口样本最少数量：`3`
- bounds viewport fit factor：`2`

这些阈值是当前版本的工程默认值，后续可以基于手感和模型规模继续调参。

### WebGL depth sampling 当前实现

当前不是遍历 CAD 业务模型做软件 raycast，而是 `webgl-engine` 内部的 screen-space depth pass。

实现链路：

```txt
editor resolveNavigationCenter
  -> context.sampleNavigationDepths(...)
  -> RenderEngine.sampleNavigationDepths(...)
  -> webgl-engine offscreen navigation depth pass
  -> gl.readPixels(...)
  -> canvasDepthToWorld(...)
  -> NavigationDepthSample[]
```

关键实现点：

- 当前已切换为 WebGL2 后端，初始化时直接请求 `webgl2` context，不再回退到 WebGL1。
- `webgl-engine` 内部类型已切到 `WebGL2RenderingContext`。
- 主渲染 shader、label shader 和 navigation depth shader 已切到 GLSL 300 ES。
- offscreen navigation depth framebuffer 当前使用 RGBA color texture + `DEPTH_COMPONENT32F` depth texture。
- depth texture 负责真实遮挡；RGBA texture 仍负责把最终可见 fragment 的 depth 和 `RenderDepthRole` 暴露给 CPU。
- shader 把 `gl_FragCoord.z` 编码到 RGB，把 `primary / secondary` 编码到 alpha。
- CPU 侧仍从 RGBA color attachment 读取编码深度，不直接用 `readPixels(DEPTH_COMPONENT, FLOAT)` 计算旋转中心，以保持交互语义稳定。
- `primary` 和 `secondary` 节点会进入 navigation depth pass。
- `excluded` / label 永远不参与 navigation depth pass，也不参与 navigation bounds。
- `canvasDepthToWorld(...)` 根据 `{ canvasPoint, depth01 }` 反投影出 `worldPoint`，同时计算 `viewDepth`。
- `includeSecondary=false` 时只返回 primary；`includeSecondary=true` 时返回 primary + secondary。
- 窗口旋转中心采样使用 `viewport-grid` 低分辨率 offscreen pass，一次 `readPixels` 读取约 `2000` 个样本，不再为窗口样本逐点 `readPixels(1x1)`。
- 主渲染、label 渲染和 navigation depth pass 都已使用 WebGL2 VAO 记录固定 attribute layout，绘制时只绑定对应 VAO。

这套 depth readback 仍沿用早期 RGBA 编码设计，切换到 WebGL2 后暂时保留以降低行为变化风险。后续可以把 RGBA depth encode 改成 WebGL2-native depth readback / 更完整的 pick-depth buffer 架构，但当前不作为本轮迁移必做项。

### WebGL2 改造当前状态

本轮 WebGL2 改造已阶段性完成并验收：

- `createWebglRenderer(...)` 只请求 `webgl2` context。
- webgl-engine 内部上下文类型使用 `WebGL2RenderingContext`。
- 主渲染、label 渲染和 navigation depth shader 都已升级到 GLSL 300 ES。
- navigation depth target 已从 depth renderbuffer 改为 depth texture。
- 主渲染、label 渲染和 navigation depth pass 都已 VAO 化。
- 刷新页面时首帧不再用 `1x1` viewport 渲染，避免 canvas 被 CSS 拉伸后出现整块蓝色闪烁。

暂不继续追加以下 WebGL2 增强项：

- MRT
- UBO
- query / timer query
- instancing
- framebuffer fallback
- render pass 大抽象

### 当前和 Onshape 仍有差距

已接近的部分：

- rotate/pan begin 时解析一次 center。
- drag 期间固定 center。
- 普通 rotate 使用 current camera up/right。
- 空白处基于当前屏幕深度样本解析中心。
- reference plane 作为第二优先级参与。
- label 不参与导航中心。

仍未实现或未完全对齐的部分：

- 没有惯性旋转。Onshape 有 inertia/velocity 路径，释放后可能继续按最后速度衰减旋转；当前实现 pointer up 后立即停止。
- 没有 constrained orbit / Alt 约束旋转。
- viewport depth sampling 还是固定步长和简单平均，没有中心权重、离群点过滤、深度聚类等高级采样质量策略。
- bounds fallback 使用当前简化规则，未完全复刻 Onshape 内部 `doBoundsFitInViewport` 相关细节。
- 没有 selected object / hovered object orbit center 策略。
- fit view / standard view / ViewCube click 已有基础平滑动画，但还没有完整视图导航菜单和拖拽 ViewCube orbit。
- 没有更完整的 up-vector 极区稳定策略。
- 当前 `webgl-engine` 已完成 WebGL2 基础迁移；长期专业 CAD 渲染内核可继续评估更完整的 WebGL2-native pick/depth buffer 或 WebGPU 路线。

### 后续建议顺序

1. 先保持当前相机基础行为稳定，不急于加惯性。
2. 若继续向 Onshape 靠，优先增强 depth sampling 质量：中心权重、离群点过滤、深度聚类、样本置信度。

```txt
cad-model -> sketch, core, math, shared
sketch    -> core, math, shared
core      -> math, shared
math      -> shared
shared    -> none
```

当前职责：

- `@occt-draw/core`：保留通用机制，包括 `DocumentOperation / DocumentTransaction / TransactionGroup / EditDraft / PayloadStore / SelectionTarget`。
- `@occt-draw/cad-model`：承接 `CadDocument / PartStudio / Feature / FeaturePayloadStore / ReferencePlaneObject / ReferenceOriginObject / createDefaultCadDocument / document queries`。
- `@occt-draw/sketch`：保留草图数据模型、草图 request、草图 transaction 和 change tracking；不再导出 `findSketchByFeatureId / getSketchForFeature / getSketchPayload`。
- `findSketchByFeatureId / getSketchForFeature / getSketchPayload` 已迁到 `@occt-draw/cad-model`，因为这是 Document/Feature 与 Sketch payload 的集成查询。

后续开发注意：

- CAD 文档、Feature 树、基准面、默认文档从 `@occt-draw/cad-model` 导入。
- 选择、draft、通用 transaction 仍从 `@occt-draw/core` 导入。
- 草图内部模型和草图 request 仍从 `@occt-draw/sketch` 导入。
