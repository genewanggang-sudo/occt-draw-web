# 草图 Profile 与封闭区总体规划

## 文档目的

本文记录 `occt-draw-web` 后续实现草图封闭区识别、Profile 数据层和 Profile 显示的总体方向。

当前草图已经具备基础曲线绘制能力，但 CAD 中的草图不能只停留在“画出线”。草图曲线需要动态生成可选择、可显示、可被特征消费的封闭区域。后续拉伸、旋转、扫掠、放样等特征都应基于稳定的草图 Profile，而不是直接读取散乱的曲线实体。

本文只作为总体规划，不执行具体编码。真正实施前仍需按仓库 `AGENTS.md` 要求，单独确认包职责、改动边界、public API 和依赖关系。

## 背景

当前仓库中的草图相关职责大致如下：

- `@occt-draw/math`
    - 负责通用 2D/3D 数学和几何算法。
    - 不理解 Sketch、Feature、Document、Canvas 等业务语义。
- `@occt-draw/sketch`
    - 负责草图领域模型、草图曲线、点、顶点、边、约束/尺寸/Profile 占位。
    - 当前 `SketchProfiles` 还只是占位，未真正生成闭合区数据。
- `@occt-draw/cad-model`
    - 负责 CAD 文档、Part Studio、Feature、Sketch payload 以及文档级请求。
    - 不应直接实现底层 profile 几何算法。
- `@occt-draw/cad-canvas`
    - 负责把 CAD / Sketch / Draft 转成通用 CanvasScene / CanvasObject。
    - 未来应读取 Sketch Profile 显示模型，生成封闭区填充和选择命中对象。
- `@occt-draw/editor`
    - 负责命令、交互、选择、编辑会话。
    - 后续应通过文档级 request 或公开查询使用 profile，不应直接拼装草图拓扑。

因此，Profile 能力的核心应落在 `@occt-draw/sketch`，底层纯几何辅助能力落在 `@occt-draw/math`，显示翻译落在 `@occt-draw/cad-canvas`，特征消费由 `@occt-draw/cad-model` 后续承接。

## 外部参考

### CGAL 2D Arrangement

CGAL `Arrangement_2` 把一组平面曲线诱导出的平面分割表示为 DCEL。每个 vertex 关联平面点，每条 edge 关联一段 x-monotone 曲线，face 表示最大连通区域。

参考：

- https://doc.cgal.org/latest/Arrangement_on_surface_2/classCGAL_1_1Arrangement__2.html

对本项目的启发：

- 草图封闭区不应只找“某几条边首尾相接”的简单 wire。
- 更通用的模型是：先把所有草图曲线 imprint 到同一个平面 arrangement，再从 arrangement 的 face 中提取 bounded regions。
- 交叉线、相交圆、多区域草图、内环孔洞，都属于平面分割问题。

### Onshape Sketch Region

Onshape FeatureScript 中 `qSketchRegion` 表示 sketch 产生的 fully enclosed 2D regions，并提供 `filterInnerLoops` 参数用于过滤完全包含在其他 region 内部的区域。

参考：

- https://cad.onshape.com/FsDoc/library.html

对本项目的启发：

- Sketch region / profile 是草图求解后的派生结果，而不是用户直接画出来的一条 entity。
- 同一组草图边可能生成多个区域，例如两个相交圆会生成多个 bounded regions。
- 后续 Feature 应选择 region/profile，而不是只能选择原始草图边。

### OCCT Wire / Face

OCCT `BRepBuilderAPI_MakeFace` 可以基于 plane + wire 创建 face。`ShapeAnalysis_FreeBounds` 可以把 wire 分成 closed / open，或提取 closed sub-wires。

参考：

- https://dev.opencascade.org/doc/refman/html/class_b_rep_builder_a_p_i___make_face.html
- https://dev.opencascade.org/doc/refman/html/class_shape_analysis___free_bounds.html

对本项目的启发：

- OCCT 是最终生成 B-Rep face / solid 的内核入口，但不应替代前端草图层的 profile 识别数据结构。
- 前端草图层需要维护可显示、可选择、可追踪的 ProfileRef。
- 真正执行拉伸等特征时，再把 Profile loop 转换成 OCCT planar wire / face。

## 目标

### 近期目标

1. 能在每次草图曲线变化后，重新计算当前草图中的最新封闭区。
2. 能在视口中显示封闭区填充。
3. 能让选择系统区分草图边、草图顶点和草图 profile。
4. 能为后续拉伸特征提供稳定的 `SketchProfileRef`。

### 中期目标

1. 支持线段、圆、圆弧、椭圆、椭圆弧参与 profile 识别。
2. 支持交叉曲线自动 imprint，识别多个局部封闭区域。
3. 支持 Profile 外环和内环，表达带孔区域。
4. 支持 Profile 失效检测和引用重匹配。

### 非目标

本文不规划：

- 约束求解器。
- 尺寸驱动重算。
- OCCT B-Rep 特征建模细节。
- 增量 arrangement 更新。
- 高性能大规模草图优化。
- 第三方几何库引入。

## 核心概念

### Sketch Curve

用户绘制的原始草图几何，例如 line、circle、arc、ellipse。它有原始 entity id，并可被编辑、删除、约束。

### Sketch Edge

当前模型中已有的拓扑边，连接 start vertex 和 end vertex，并引用 curve。它是草图内的基础拓扑实体。

### Imprinted Edge

Profile solver 运行时从原始 edge / curve 派生出的原子边。

例如一条线段被另一条线段穿过，应被拆成两段或多段 imprinted edge。Imprinted edge 应保留来源 curve id、原始 edge id、参数区间和方向。

### Half Edge

用于遍历平面分割面的有向边。每条 imprinted edge 生成两个方向相反的 half edges。

### Profile Loop

一个闭合边界 loop。它由一组 half edges 顺序连接形成，可计算方向、面积、包围盒和 centroid。

### Sketch Profile

一个可被选择和特征消费的封闭区域。它通常包含：

- 一个 outer loop。
- 零个或多个 inner loops。
- 面积、包围盒、centroid 等派生属性。
- 稳定 id 或 signature。
- 来源 edge / curve refs。

## 总体算法

### 1. 收集候选边

从 sketch 中读取 normal edge，排除 construction edge。缺失 curve、缺失 vertex、端点非法、长度退化的边应进入诊断信息，不参与 profile。

完整圆这类没有显式 start/end vertex 的曲线需要单独处理。早期可以把完整圆作为特殊 closed curve；后续在统一 arrangement 中也应能被其他曲线交点拆分。

### 2. 计算交点与端点合并

在 2D 草图平面内计算所有候选曲线之间的交点。

早期 MVP 可以先支持 line segment 与 line segment：

- 端点相同或距离在 tolerance 内，应合并为同一个 arrangement vertex。
- T 型相交应在被穿过的线段上插入 split point。
- X 型相交应同时拆分两条线段。
- 重叠线段应作为前置复杂情况处理，先记录诊断，避免生成不可靠 profile。

后续扩展到：

- line-circle
- line-arc
- circle-circle
- arc-arc
- ellipse / elliptical arc 相关交点

### 3. 拆分为原子边

每条原始边按参数排序后的 split points 被拆成 imprinted edges。

每个 imprinted edge 应记录：

- 来源 edge id。
- 来源 curve id。
- 参数区间。
- start arrangement vertex。
- end arrangement vertex。
- role。
- curve kind。

显示可以采样，但 profile 数据不应只保存采样 polyline。后续特征需要尽量保留原始曲线参数区间。

### 4. 构建平面图

用 arrangement vertices 和 imprinted edges 建立 planar graph。

每个 vertex 保存所有 incident half edges。每个 incident half edge 根据离开顶点时的切线角度排序。

对线段而言，角度来自 `atan2(dy, dx)`。对圆弧、椭圆弧而言，角度应来自曲线在该端点处的切线方向。

### 5. 遍历 face loop

对每条未访问 half edge，按固定规则选择下一个 half edge，遍历得到一个 loop。

常见策略：

- half edge 到达顶点后，找到其 twin 在该顶点的排序位置。
- 选择相邻方向的下一条边，保持面始终位于遍历方向的一侧。
- 遍历闭合后得到一个 candidate loop。

通过 signed area 区分：

- 外部无限 face。
- 有效 bounded face。
- 退化 loop。

项目内部可以约定 outer loop 使用统一方向，例如 counter-clockwise；inner loop 使用相反方向，或在 profile 组装时统一规范化。

### 6. 组织内外环

对所有 bounded loops 计算面积、centroid、bbox。

通过 point-in-polygon / containment 判断 loop 的包含关系：

- 没有被其他 loop 包含的正面积 loop，可作为 outer loop。
- 被 outer loop 包含且方向相反的 loop，可作为 inner loop。
- 多层嵌套需要按奇偶层级或 winding 规则组织。

早期线段 MVP 可以只支持无孔 profile。支持孔洞前，应补足稳定测试。

### 7. 生成稳定 ProfileRef

Profile 是派生结果，但后续 Feature 需要引用它，因此必须有相对稳定的身份。

可以考虑使用 signature：

- 边界来源 edge id 集合。
- 每条边的方向。
- 参数区间。
- loop 的几何 hash。
- centroid / area 作为辅助匹配。

当草图轻微编辑但拓扑未改变时，ProfileRef 应尽量保持稳定。当拓扑改变导致 profile 消失时，引用应明确失效，而不是静默指向错误区域。

### 8. 输出 Profile 诊断

Profile solver 不应只返回成功结果。它还应返回诊断信息，便于 UI 和后续调试：

- open chain。
- dangling edge。
- overlapping edge。
- degenerate edge。
- unsupported curve intersection。
- self-intersecting loop。
- ambiguous containment。

早期可以先内部使用诊断，不急着做 UI 暴露。

## 数据层规划

### SketchProfiles

当前 `SketchProfiles` 只是占位。后续应扩展为草图派生 profile 集合。

建议数据结构方向：

```ts
interface SketchProfileSnapshot {
    readonly id: SketchProfileId;
    readonly kind: 'profile';
    readonly outerLoop: SketchProfileLoopSnapshot;
    readonly innerLoops: readonly SketchProfileLoopSnapshot[];
    readonly area: number;
    readonly centroid: Vector2;
    readonly sourceSignature: string;
}

interface SketchProfileLoopSnapshot {
    readonly segments: readonly SketchProfileSegmentSnapshot[];
    readonly signedArea: number;
}

interface SketchProfileSegmentSnapshot {
    readonly sourceEdgeId: SketchEdgeId | null;
    readonly sourceCurveId: SketchCurveId;
    readonly parameterStart: number;
    readonly parameterEnd: number;
    readonly reversed: boolean;
}
```

具体字段需要等实施前结合现有 `Curve2D` 参数模型再定，不应在本文中提前冻结 public API。

### 派生状态还是持久状态

Profile 本质上是草图曲线的派生结果。建议采用“模型中可查询，但由 solver 重建”的方式：

- Sketch 保存当前 `profiles` 派生集合。
- 每次 sketch edit 后同步重算。
- undo / redo 回放 sketch entity change 后，也重算 profile。
- 不允许业务代码手动编辑 profile 几何。

这样可以让显示和选择有稳定入口，同时避免 profile 成为另一份需要手动维护的真源数据。

## 显示规划

`SketchDisplayBuilder` 当前只输出 edges、vertices，`profiles` 是空占位。后续应增加 profile 填充输出。

显示模型可以包含：

```ts
interface SketchDisplayProfile {
    readonly ref: SketchEntityRef;
    readonly outerLoop: readonly Vector3[];
    readonly innerLoops: readonly (readonly Vector3[])[];
    readonly centroid: Vector3;
}
```

这里的 `Vector3[]` 是显示三角化或填充前的轮廓采样结果，不等于 profile 的数据真源。

显示层注意事项：

- Profile 填充应是半透明、低优先级，不遮挡草图边。
- Hover / selected 状态应能高亮 profile 区域。
- 边和 profile 重叠时，拾取优先级需要明确，通常草图边/点优先于填充面。
- 内环孔洞不能被填充。

## 特征消费规划

后续拉伸特征不应直接读取草图曲线集合，而应读取 `SketchProfileRef`。

大致流程：

```txt
ExtrudeRequest
  -> resolve SketchProfileRef
  -> profile outer/inner loops
  -> build OCCT planar wires
  -> BRepBuilderAPI_MakeFace
  -> prism / boolean / feature result
```

这样可以保持：

- UI 选择的是封闭区。
- 文档记录的是 profile 引用。
- 几何内核消费的是明确 wire / face。

## 分阶段路线

### 阶段 1：线段 Profile MVP

范围：

- 只支持 line segment。
- 支持矩形、多边形、多个独立闭合区。
- 支持 X / T 交点拆分。
- 暂不支持重叠边。
- 暂不支持孔洞。

涉及方向：

- `@occt-draw/math`
    - 完善 segment intersection、point merge、polygon orientation / containment 所需能力。
- `@occt-draw/sketch`
    - 新增内部 profile solver。
    - 扩展 `SketchProfiles` 数据模型。
    - 在 sketch 修改后重算 profiles。
- `@occt-draw/cad-canvas`
    - 显示 profile 填充。

### 阶段 2：选择与显示闭环

范围：

- Profile hover。
- Profile selected。
- Inspector 或状态栏能识别当前选中对象是 profile。
- profile ref 可以进入 selection set。

涉及方向：

- `@occt-draw/sketch`
    - 提供 profile refs 和 display data。
- `@occt-draw/cad-canvas`
    - 生成 profile pick object。
- `@occt-draw/editor`
    - 处理 profile selection 语义。

### 阶段 3：圆和圆弧参与 Profile

范围：

- 完整圆形成单独 profile。
- 圆与线相交后产生多个区域。
- 圆弧可以参与闭合 loop。

关键点：

- 数据层保留 curve parameter range。
- 显示层采样不应污染 profile 真源。
- 切线角排序要支持曲线端点方向。

### 阶段 4：内环与多区域

范围：

- 支持一个 outer loop + 多个 inner loops。
- 支持嵌套 loop containment。
- 支持 profile 面积、centroid、bbox。
- 支持类似 `filterInnerLoops` 的查询策略。

### 阶段 5：特征接入

范围：

- Extrude 选择 sketch profile。
- Profile 转 OCCT planar wire / face。
- 草图修改后 feature 引用失效或重匹配。
- 后续扩展到 revolve / sweep / loft。

## 风险与注意事项

### 数值鲁棒性

Profile solver 会高度依赖 tolerance。点合并、交点、参数排序、面积判断必须统一容差策略。

早期不要追求 exact arithmetic，但要避免每个模块各自写一套容差。

### 重叠边

重叠边比普通相交复杂，会影响 arrangement 的拓扑归属。MVP 可以先识别并诊断，不生成 profile。

### 自相交曲线

自相交 loop 不应直接当作 profile。应先被 imprint 成多个 bounded regions，或标记为 unsupported。

### 稳定引用

Profile 是派生结果，稳定 id 是后续特征可靠性的关键。不能只按数组顺序分配 id。

### 显示采样与真实几何

显示可以采样曲线，Profile 数据层不能只保存采样点。否则后续拉伸生成的 B-Rep 会丢失圆弧、椭圆弧等真实几何。

## 建议验收用例

阶段 1 至少覆盖：

- 单矩形生成一个 profile。
- 两个分离矩形生成两个 profile。
- 三角形生成一个 profile。
- 开口折线不生成 profile。
- T 型交点不会误生成 profile。
- X 型交叉矩形可拆分为多个 bounded regions。
- construction line 不参与 profile。
- 删除一条边后 profile 消失。
- 移动顶点后 profile 更新。

阶段 3 后补充：

- 完整圆生成一个 profile。
- 圆与线相交后生成多个 region。
- 圆弧 + 线段闭合生成 profile。
- 两个相交圆生成多个 bounded regions。

阶段 4 后补充：

- 外矩形 + 内矩形生成带孔 profile。
- 多个孔洞。
- 嵌套环。

## 总结

草图 Profile 不只是显示效果，而是从草图绘制走向特征建模的核心桥梁。

推荐路线是：

```txt
Sketch curves
  -> 2D imprint / arrangement
  -> half-edge face traversal
  -> bounded profile regions
  -> display / selection / feature references
  -> OCCT wire / face
```

短期先用全量重算实现线段 MVP，建立正确的数据边界和测试样例。等线段 Profile、显示和选择闭环稳定后，再扩展圆弧、内环和特征接入。
